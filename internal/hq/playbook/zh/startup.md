# 启动、唤醒与交接

## 启动或接班

先应用入口章程和 LOCAL。读态势板、任务台账、`gtmux digest --json` 和工作台手册。行动前对账持续目标。简短说明 HQ 身份和当前状况，把用户待决放前，写清未知覆盖。按存活窗格记录目的、状态和派发渠道。摘要不清楚时，在跟进范围内只看一次轨迹开头。收到 `new-session` 只增量建联该会话。

全新目录且 LOCAL 仍是空模板时，可一次性询问主要项目、汇报和安静时段，记录用户实际给出的偏好。升级、重启和轮换继承原有政策与交接。沿用态势板原语言与种子标题。在 `## ① 现状 — 在跑的 pane` 每个存活窗格一行，在 `## ② 交接记录 — 新的在最上面` 把近期交接按时间倒序写。用真实窗格 ID 定位。已有 `### 还等你定的` 节只留真实待决，处理后及时撤下。过程留在原证据。态势板存当前判断和引用，持久经验进知识库。

## 唤醒或疑似丢唤醒时拉取

- `» gtmux·<class>` 表示关注顺序。从 HQ 主目录或其子目录用消费水位拉连续、不过滤的增量。先保留并审阅全窗格及事件类型，再下钻。即使下游 shell 过滤掉部分记录，CLI 也可能已确认整个增量。
- HQ 根目录的常规读省略本窗格回显、不计债的生命周期闪断与 `gtmux:audit:*`。用 `--all` 查看这些事实。子目录读可计消费并显示原始视图。使用实际 CLI 游标。过滤、跳读和有断档的读不还债。`--severity notable` 用于舰队变化，`--severity important` 用于升级筛选。通过独立证据核完某段后才用 `gtmux events --ack`，并读回回执。
- `unread` 是未消费输入。已处理的同一 `#<id>` 是重发。对短 ID、投递时刻、源事件和消费。已排队的旧提醒可能在源已处理后才进入回合。视图不全时对照 `gtmux digest --json`、工作台核对、未归属的直派及结束报告。安静和缺唤醒期间责任仍在。
- `wake-degraded` 到来先核事实。把事件产生、唤醒送达、HQ 实际消费及下一责任分别验证。已恢复就静默记账，核心能力仍失效时说明范围与安全恢复或介入步骤。机械恢复由常驻服务负责，项目或服务修复遵守角色和审批边界。
- 核真实出处。HQ 自身窗格中，真实用户的 `UserPromptSubmit` 与 HQ 自己的 `Stop` 来源不同。转送输入须核原事件的身份和时刻。`(slash-command)` 表示用户实际在工具上操作，本身不给后续动作授权。
- 执行者提问、结束、崩溃、目标变化、资源预警和回收走派发手册。`distill` 与 `self-check` 及相应控制记录 走维护手册。遇 `agent-relay` 提醒先读持久回执，即使提示已被接受。`tunnel` 断开或恢复须核现状，断开期间计入手机无法送达的影响。
- `waiting`、`asks` 和 `stuck·waiting` 先核来源再上交真实问题。`resolved` 经核实后清原待决。`done` 和 `crash` 对实际证据。`goal-changed` 保留用户直派目标。`reap-suggest`、`resource·warn`、`limits·warn` 或 `usage·warn` 走派发手册。

## 呈现关键变化

状态询问先给当前计数和简短对齐表格。用户待决排最前，其后是进行中和实际存在的完成或失败行。用 `gtmux usage`、`gtmux limits` 补用量汇总、会话压力和订阅窗口。查 `gtmux resource`，用电池或低电时写电源状态。根据 `gtmux quiet status` 和用户偏好呈现唤醒。例行信号入账。变更简报用短 `⟣ ◈`，验证完成用 `⟣ ✅`，异常用 `⟣ ⚠`，用户对话用自然语言。升级前重核来源，及时撤下已处理问题。

趁决定还能改时给出实测事实、选择、代价及建议。用 `gtmux advice` 记重要建议和实际处置。实质歧义、明确缺口或真实等待需暂缓时，说明按住什么、为什么和恢复条件。已决定且获授权的工作继续。`tick` 只报变化，简报最多六行。

## 轮换

收到 `self-rotate` 时记录未完工作、证据、待决、暂停、下次检查和已验证的驱动或 HQ 责任。更新态势板和工作台再运行 `gtmux hq --rotate`，结束回合让常驻服务处理空闲且无草稿的输入。排队回执只是暂态。Codex 要核新会话和可恢复的首轮活动，并确认继任者接棒。Claude 核新会话及责任恢复。ID 未变先核原轮换回执。保留草稿和未知结果，避免盲重置。手动恢复查 `gtmux hq --help-all` 和当前诊断。
