# 派发、跟进与回收

## 分派前

核当前范围、既有驱动和会话跟进许可。建议或派发前按维护手册查知识。读实时摘要与任务回执。保持既有窗格用途，新开执行者前核仓库及 `--cwd`。独立步骤分别交给能自汇报的执行者，快速收尾与慢构建或发版分开，窗口及 worktree 按任务命名。按任务和预算明确选 agent 与模型，有合适轻档就用。配额或上下文紧张时缩小扇出，依赖压缩结果前先核已完成。

按 LOCAL 和任务的可见性需要选择可见或后台派发，后台用于合适的工作。查已装 `gtmux spawn` 帮助中的 `--headless` 与 `--oneshot`。交互可见性和一次性进程是两个决定。DSH 终端沿用客户端所选模型，省略通用 `--model` 和 `--oneshot`。

用 `gtmux spawn`、明确项目目录及 `--goal-file`。安全写字面文本，例如引用 heredoc `<<'EOF'`，命令参数会先经 shell 解析。任务文件带目标、范围、授权、验收证据、报告、存储及适用的机器或项目规则。有工作台事项时精确绑定，派发后报告实选 agent、模型、会话定位和标题。派发失效后先核本次结果及已有任务，再走受支持入口重试，保留无关进程和状态。

## 发送、验收与跟进

先写消息文件，核目标最新身份、运行状态及用户指令。若目标正在工作，等自然断点，或为独立工作使用获准的并行 worktree。指定复用项目执行线不等于授权打断。按需用 `tmux capture-pane -e` 抓取输入区域，读回并判读，另起调用再决定是否发送。保留用户真实草稿，包括预检后才出现的输入。屏幕不明或工具拒绝时暂停。禁止送导航键、清输入、用 `--force` 越过门禁或换渠道绕拒绝。已授权跟进走 `gtmux send --message-file` 或工作台受追踪意图。表单无法判读时，可让用户在准确会话处理。

用准确回执或目标源历史验证送达。排队保持待接收，提交回执与开始执行分开核。区分身份、接收、开工、结果和验收。Stop 承诺之后还做时，找原生目标、可自动返回的后台回调或明确责任人。已有驱动则继续观察。无人推进时按工作台手册落实可核下一步或明确等待。斜杠命令、执行错误或连接中断都不足以证明任务完成。报告实际结果、剩余缺口和下一责任。

## 资源与回收

加负载前查磁盘、内存、CPU、电池和订阅配额。磁盘红档先压高写入任务。协调有界的低写入盘点，优先处置已授权的可再生、未使用材料，处置后实测空间。保留策略有待选择时交用户，避免过期或重复建议。电量低且放电时及时提醒接电。用实际资源读数说明影响。

正常回收先验证完成及批准范围。按实际情况点名会话、窗口、worktree 和分支。核标题、真实身份、草稿、所有权、仍运行的工作、正式证据及保留要求。已有单次批准或 LOCAL 常设许可沿用到其准确范围。未授权不可逆操作交用户批准。用 `gtmux reap` 或获准执行者清理，再核实际资源变化，独立记录事项后续责任。拒绝后保留工件，按 CLI 支持的方式暂缓建议。启动失败遗留临时窗口时，先核归属、ID 和使用状态，再按适用的常设许可处置或提出建议。
