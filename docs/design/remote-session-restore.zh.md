# 在 App 中恢复服务器会话

[English](remote-session-restore.md)

打开「服务器」，在对应服务器的更多菜单中选择「恢复会话」。先核对存档时间和缺失会话，再开始。恢复会载入存档布局，按页面显示的服务器设置启动助手或仅预填命令，不会发送新任务。已在运行或只是未连接终端的会话不在远程启动范围内。服务器仍使用其已信任的 tmux-resurrect 安装及配置的钩子；这是所有者的操作能力，不用于执行不可信存档。

页面分别显示准备、布局恢复、助手启动，以及已确认、待确认、跳过或失败的结果。手机和平板可滚动查看，也支持放大字体。可以离开页面，重新打开读取服务器上同一次任务的进度。只有明确点击开始或重试才提交操作；回复丢失时保留原请求编号。切换服务器后，旧页面的迟到结果不会覆盖新页面，也不会向新目标发送旧请求。访客和演示模式不提供恢复，旧服务器会提示升级。

核心先保存私有回执，再启动一个后台子进程。子进程与 CLI、菜单栏使用同一内核进程锁，重新核对预览，先恢复布局而不启动助手，再复核获准的存档输入，最后只对本次批准的缺失会话和身份使用原有助手恢复逻辑。发送前还要核对窗格位置和 shell。远程任务不会打开本机终端。中断不会自动重跑，启动命令已发送也不会算作会话已经恢复。菜单栏恢复时保留原有进度，手动点击外部或按 Escape 仍可关闭。

接口详见 api/contract.md，不返回私有命令、路径和历史提示词。新请求编号超过24小时不再受理；终态回执至少保留48小时，最多128条，容量或读写异常时拒绝操作。所有本地和 CI 验证使用隔离 HOME、合成 tmux 和网络夹具，不实际恢复用户旧会话。真实重启恢复和安装后的界面交互仍需单独验收。

仅凭 frontend403 截图不能判断是 Codex 的会话数量限制。桥接层在进程、存储目录、TTY 或身份明确不符时返回403，暂缺观测或超时时返回503。应按时间核对 `codex.frontend.startup.*` 的具体原因；恢复的旧终端画面可能早于当前启动日志。不能遇到拒绝就自动重试或重放用户任务。
