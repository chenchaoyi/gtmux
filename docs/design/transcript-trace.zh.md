# 会话轨迹：浏览器与原生 App

## 当前交付范围

浏览器与原生 App 使用同一份会话索引。所有者与完整权限配对设备还可读取明确记录的上下文；访客保留原有公开消息范围。“对话 / 终端”仍是显示模式，轨迹与 Diff
从会话工具进入。实现与自动化检查不代表真机、VoiceOver 已验收。原生入口是
`mobileapp/src/screens/DetailScreen.tsx` 的 `DetailMode`；正文由 `ui/ChatView.tsx`
展示，外部会话复用 `state/useDesktopTranscript.ts` 读取。

基础能力不需要新增服务端接口。现有窗格与外部会话接口已经提供按顺序排列的用户消息、
助手正文、session 身份和已记录的调用参数。DSH 的模型请求计时、Token 统计、私有思考
和工具输出不在这份契约里，界面应明确显示已有记录的范围。

## 浏览器交互

进入轨迹后，可以搜索、按记录类型筛选，再选择消息或调用。列表标明 Agent、已加载的
轮次和历史会话边界；调用详情保留参数缩进、工作目录和截断提示。详情提供概述、预览、
原始内容与来源，复制默认取原文，「来源」页复制来源 JSON。

宽视图允许列表与详情并排。窄面板把整个阅读区交给详情，关闭后回到原选中行；桌面的
小面板也遵循此规则，不依赖浏览器总宽度。关闭工具后保留底下的查看模式、草稿和阅读位置。
对话和终端保留输入区，轨迹将这部分空间用于阅读。

概览覆盖全部筛选结果，通过原生滑杆支持触摸和键盘定位。搜索覆盖全部已加载记录，
列表每页最多渲染 200 行，包含折叠分组行，并提供前后翻页。打开轨迹时直接定位到最新载入的记录，空闲会话也一样，不再提供跟随模式开关。轮询保留选择、展开状态和可见行锚点；停在底部时继续跟随，查看旧记录时暂停。离开底部后只提供一次性的返回最新按钮。选中文字或聚焦详情控件时，保留当前显示版本，释放后再更新。
会话状态来自 Agent 列表，不从正文推断工具是否完成；筛选到旧 session 时显示“历史会话”。

## iPhone 交互

保留“对话 / 终端”显示模式，轨迹与 Diff 从独立会话工具进入；字号沿用现有显示菜单。
普通 shell 仍只有终端；可读的外部会话使用只读对话，并可打开轨迹工具，
无法读取正文的原生会话继续只显示状态。

轨迹默认定位到最新活动，顶部用紧凑摘要说明本轮最近的公开进展。时间线按准确的会话与稳定轮次身份分组：最新轮展开，历史轮先显示请求摘要。连续调用合成带数量的组，展开后每次调用仍可独立检查；图标与顺序线区分请求、公开回复和调用，不推测工具是否成功。搜索从顶部打开并覆盖所有已加载记录，包括折叠内容；一个筛选菜单容纳类型和易读的会话名称。点记录后详情覆盖在仍挂载的列表之上，
关闭时恢复同一行、滚动位置和筛选条件。详情复用 App 的字号、原生选字和复制控件；
代码保留缩进，长行在代码区域内部滚动。复制、关闭等按钮至少提供 44pt 触摸区域和清楚
的读屏名称。Agent 与说话人头像复用 `ParticipantProfileModal`，保留“当前资料”与
“这条消息当时的记录”的区分。

查看旧记录时不被新消息拉回底部，选字也不被刷新打断。停止跟随后，应有明确的返回最新
记录入口。当前活动状态与历史记录分开呈现，轨迹里不重复放一套对话输入框。

## iPad 交互

按实际内容栏宽度判断布局，覆盖分屏和台前调度。内容栏能容纳约 300pt 列表与足够宽的
详情时再采用双栏，当前阈值为内容宽度 820pt 且字体缩放小于 1.6；更窄时使用与 iPhone 相同的点入详情
流程。辅助功能大字号可能需要更早切换为单栏，不应只根据“是不是 iPad”判断。

关闭详情后列表扩展。旋转、缩放窗口保留所选记录及阅读位置；原生选字与键盘焦点优先于
新记录的自动更新。明暗模式沿用 App 的现有设置。

## 实现与验收

`mobileapp/src/trace/model.ts` 是唯一纯数据索引模型，`scripts/gen-trace-web.cjs`
生成浏览器副本；两端共享合成样例，并校验生成物。不要把浏览器
DOM 搬进 WebView，也不要另写一套读取 Agent 私有日志的逻辑。`DetailScreen`、HQ 和外部只读会话的轨迹
共用各自已有的订阅；在对话中打开工具不会重启读取。轨迹首次打开再挂载，身份、home
或凭据变化时取消旧请求并清除旧记录、选择与资料卡。外部会话返回 401/403 时清除缓存
并关闭工具；普通网络失败保留同一会话缓存，提供重试。记录 key
利用 home、session 和已有的消息身份；没有时间且内容完全相同的记录存在顺序判别边界，
后续服务端稳定记录 ID 可以改善这一点。

原生验收应覆盖五类 Agent、HQ 跨会话历史、同 ID 不同 home、缺时间或参数、截断、迟到
响应、撤销、长历史、流式更新中的选字、320pt 宽度、大字号、iPad 窗口变化和 VoiceOver。
浏览器的测试与截图不能替代这些原生验收。

详情固定当前所选正文及其历史说话人；流式更新只提示“更新详情”，不会直接替换正在阅读
的版本。文件通过现有文档桥，使用该条记录的 session 和当前 home。状态徽章表示列表中
会话的状态，不推断工具结果；没有时间就不显示。记录范围说明默认收起。

HQ 可通过已有历史读取加载更早会话。加载为明确操作，期间禁用重复点击；加载后的
历史进入同一套会话筛选，保留固定选择，不另起订阅。

紧凑详情暂时收起搜索、筛选和浏览器概览，让参数使用完整阅读高度；关闭后恢复控件及其
原有条件。

## 设计参考

本轮参考 Langfuse 的[会话分组](https://langfuse.com/docs/observability/features/sessions)与[重复步骤聚合](https://langfuse.com/docs/observability/features/agent-graphs)，以及 Chainlit 的[消息／步骤区分](https://docs.chainlit.io/concepts/step)，沿用 gtmux 自身的图标、状态配色和调用参数记录边界。OpenCode 的[滚动锚点缺陷记录](https://github.com/anomalyco/opencode/issues/17996)提醒：显式定位和用户滚动应优先于刷新补偿。这些是官方文档与源码记录对标，不冒充外部产品的现场交互验收。

## 独立折叠与已记录上下文

浏览器、iPhone 和 iPad 都提供独立的「轮次」「调用」批量开关。轮次收起或展开整轮；
调用把每段连续调用收成「N 个工具调用」及工具名称，1 次、2 次也适用，单组仍可独立展开。
批量选择适用于后续新记录，单组选择在同一会话刷新后保留。筛选临时展开匹配项，清除后恢复原状态。
折叠导致列表变短时，程序触发的滚动不会自动恢复跟随；手动滚动或「回到最新记录」才会恢复。
若所选记录已收起，关闭详情后焦点回到可见的上级折叠行。

上下文按来源顺序展示：前置指令放在真实提问之前，运行提醒和后台通知保留在过程中的位置，
不冒充用户消息，也不在对话中生成空白气泡。详情有「概述／预览／原始内容／来源」四页；
预览排版正文与已记录 JSON，原始内容保留文字和缩进。复制默认取原文，「来源」页复制来源 JSON。
原生端四页共用固定的所选版本；更新须由用户主动采纳。
来源只展示真实的 Agent、记录类型、会话、轮次和已有时间，明确区分本轮开始与记录时间，
不推测模型请求全文、RPC ID、Token、调用耗时、结果或私有思考。

| Agent | 可读取的上下文 |
| --- | --- |
| Codex | 已知工作区／环境输入，以及用户记录中完整的 system-reminder、task-notification 包装 |
| Claude Code | 用户文本中完整的环境包装和明确标记的压缩摘要 |
| Kimi | 已知注入、技能启用、系统触发、hook 结果与压缩摘要输入 |
| DeepSeek Harness | 公开 injection 追加记录与已知环境包装，不读取回放或私有思考 |
| OpenCode | 当前 hook 日志没有这类内容，不重建；上下文筛选为空时说明未记录 |

每条最多保留 8 KiB UTF-8 文本，每轮最多 32 条、合计 64 KiB；保留的部分内容带截断提示，
同时受已有响应体与缓存预算约束。新版阅读器用 `context=1` 明确请求上下文；旧服务端可忽略该参数，旧客户端继续收到原有段落结构。
`segments[].context` 只向明确请求的所有者及完整权限配对设备提供。
访客响应会移除此字段及空的上下文段落，条件缓存版本按受众隔离；原有公开提问和回复不变，
分享权限不扩大。旧客户端可忽略新字段。测试只使用合成记录，不保存真实私有对话或隐藏请求。

本轮参考用户提供的 DSH Web 截图，学习独立折叠、调用分组、四页详情和设置导航的交互。
截图中的计时和 Token 数据不在 gtmux 现有记录范围内，不作推测。

原生 Trace 的详情将长输入按阅读区域宽度换行，不再要求横向拖动；复制仍保留原始空白和完整的已记录内容。工具分组只显示数量与工具名称，每条调用可分别打开。
