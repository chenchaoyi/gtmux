# 会话轨迹：浏览器交互与 App 方案

## 当前交付范围

浏览器已提供基于公开会话记录的轨迹页。原生 App 目前只有“对话 / 终端”，本文的
App 轨迹是设计建议，尚未实现，也未完成原生设备验收。现有入口是
`mobileapp/src/screens/DetailScreen.tsx` 的 `DetailMode`；正文由 `ui/ChatView.tsx`
展示，外部会话复用 `state/useDesktopTranscript.ts` 读取。

基础能力不需要新增服务端接口。现有窗格与外部会话接口已经提供按顺序排列的用户消息、
助手正文、session 身份和已记录的调用参数。DSH 的模型请求计时、Token 统计、私有思考
和工具输出不在这份契约里，界面应明确显示已有记录的范围。

## 浏览器交互

进入轨迹后，可以搜索、按记录类型筛选，再选择消息或调用。列表标明 Agent、已加载的
轮次和历史会话边界；调用详情保留参数缩进、工作目录和截断提示。正文可在预览与原文间
切换，复制取得该条记录的原始文字。

宽视图允许列表与详情并排。窄面板把整个阅读区交给详情，关闭后回到原选中行；桌面的
小面板也遵循此规则，不依赖浏览器总宽度。关闭工具后保留底下的查看模式、草稿和阅读位置。
对话和终端保留输入区，轨迹将这部分空间用于阅读。

概览覆盖全部筛选结果，通过原生滑杆支持触摸和键盘定位。搜索覆盖全部已加载记录，
列表每页最多渲染 200 条，并提供前后翻页。轮询保留选择和展开状态；检查旧记录或手动
滚动会停止跟随最新。选中文字或聚焦详情控件时，保留当前显示版本，释放后再更新。
会话状态来自 Agent 列表，不从正文推断工具是否完成；筛选到旧 session 时显示“历史会话”。

## iPhone 方案

保留“对话 / 终端”显示模式，轨迹与 Diff 从独立会话工具进入；字号沿用现有显示菜单。
普通 shell 仍只有终端；可读的外部会话使用只读对话，并可打开轨迹工具，
无法读取正文的原生会话继续只显示状态。

轨迹首先显示可虚拟化的记录列表，顶部提供搜索与紧凑的类型筛选。点记录进入详情页，
返回时恢复同一行、滚动位置和筛选条件。详情复用 App 的字号、原生选字和复制控件；
代码保留缩进，长行在代码区域内部滚动。复制、关闭等按钮至少提供 44pt 触摸区域和清楚
的读屏名称。Agent 与说话人头像复用 `ParticipantProfileModal`，保留“当前资料”与
“这条消息当时的记录”的区分。

查看旧记录时不被新消息拉回底部，选字也不被刷新打断。停止跟随后，应有明确的返回最新
记录入口。当前活动状态与历史记录分开呈现，轨迹里不重复放一套对话输入框。

## iPad 方案

按实际内容栏宽度判断布局，覆盖分屏和台前调度。内容栏能容纳约 300pt 列表与足够宽的
详情时再采用双栏，约 820pt 可作为首轮验证阈值；更窄时使用与 iPhone 相同的点入详情
流程。辅助功能大字号可能需要更早切换为单栏，不应只根据“是不是 iPad”判断。

关闭详情后列表扩展。旋转、缩放窗口保留所选记录及阅读位置；原生选字与键盘焦点优先于
新记录的自动更新。明暗模式沿用 App 的现有设置。

## 实现与验收

App 落地时保留一份纯数据索引模型，浏览器使用生成副本，并共享样例数据。不要把浏览器
DOM 搬进 WebView，也不要另写一套读取 Agent 私有日志的逻辑。`DetailScreen` 的对话与
轨迹应共用会话订阅，轨迹首次打开再挂载；身份、home 或凭据变化时取消旧请求。记录 key
利用 home、session 和已有的消息身份；没有时间且内容完全相同的记录存在顺序判别边界，
后续服务端稳定记录 ID 可以改善这一点。

原生验收应覆盖五类 Agent、HQ 跨会话历史、同 ID 不同 home、缺时间或参数、截断、迟到
响应、撤销、长历史、流式更新中的选字、320pt 宽度、大字号、iPad 窗口变化和 VoiceOver。
浏览器的测试与截图不能替代这些原生验收。

2026-10-29 方案修正：对话/终端是显示模式；原生轨迹应从会话工具进入，与 Diff 同类，不能成为第三个并排标签。工具关闭后保留原模式、草稿和阅读位置。
