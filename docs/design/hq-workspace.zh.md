# HQ 工作台

## 1. 范围

点击菜单栏 HQ 卡片，进入原生侧栏与详情工作台。上下文是**事项**：一个持续
跟进的目标，不依赖某个窗格或某一轮 HQ 会话。本批只交付菜单栏和本地
`gtmux hq workspace` 协议，手机、iPad、Web 保留现有 HQ 界面；未增加 HTTP
写入接口或访客、分享访问。态势板、知识库、机器和用量整合进同一工作台，沿用原有数据源。

## 2. 信息与交互

首次打开显示**总览**，与侧栏共用同一份事项台账，按“待你处理／正在跟进／最近结束”
分组，不根据板上的标题或窗格活动推测事项状态。侧栏各分类可整行点击展开、收起，
显示数量和读屏展开状态；当前应用进程内，切换页面或重开窗口会保留折叠选择。
事项图标沿用会话状态：待处理为红色暂停、跟进为品牌青色圆环、结束为绿色勾，并保留文字。
侧栏还提供交代任务、与 HQ 对话、HQ 运行记录及“资料与用量”（知识库、机器、用量）。
旧态势板收为总览中的**交接快照**，保留原文、作者顺序和保存时间。各节默认收起，
不再将旧待办提为红色提示，保存的窗格编号也不再直接跳转；读取不会改写或迁移原板。事项头部显示名称、明确状态和关联会话。点击会话查看原始
记录；“在终端打开”会重新核对真实会话身份，不使用保存的窗格编号直接跳转。
没有唯一当前窗格时明确报错，已保存的原始记录仍可能可读。关联会话卡片显示
agent、当前 pane ID、位置和状态。没有匹配的当前会话时，保存的位置标为“最近
窗格”，不借用同编号新会话的状态。原始对话页提供可选择的完整会话 ID。
头部移除重复的“HQ 最新汇报”，存储的评估和下方完整对话保留。工具栏提供
刷新和终端入口；HQ 卡片右键菜单也能打开终端。

交代任务只需输入要求，首行作为可修改的事项名称。“与 HQ 对话”不创建事项。
输入框明确显示作用范围，回车换行、⌘回车发送。当前应用进程内，切换事项或
关闭窗口会保留草稿。用户 Markdown 消息靠右，沿用手机的人形电池头像；HQ
公开回复靠左，使用 gtmux 头像。名字放在气泡上方，“复制”放在正文下方，复制完整
Markdown，并短暂显示成功或失败。全局、事项和关联会话原文共用这些组件。
时间分隔沿用 App：首次有效时间、跨日或距离上次有效时间至少 15 分钟时显示。
没有时间的记录不补造日期，也不打断前后有效时间的比较。会话切换提示不会遮掉同轮正文。
工具步骤和有事件台账凭据的唤醒批次默认折叠，仅长得像信号的
用户文字不会被隐藏。读取工作台不会推进 HQ 未读水位。

管理会话可关联当前或以前记录过的 tmux 会话，选择参与执行或历史参考，并
指定时间范围。持续关联默认从当前时间开始，历史参考必须指定结束时间。
转移、移出、合并、拆分只调整归属。移出不删除源记录；合并保留消息原始归属，
读取时沿明确关系合并。拆分移动所选关联，原讨论保留在来源事项，并提供来源
事项链接，不补造一份历史对话。标题、项目目录、进程名、窗格编号都不是聚合
依据。本功能不会自动把原生桌面会话纳入 HQ 跟进。

## 3. 模块与协议

- `internal/hqworkspace`：数据模型、原子快照、事务、关联、消息、回执和操作记录，
  不依赖界面或 tmux。
- `internal/app/hqworkspace*.go`：本地命令适配、来源读取、HQ 目标核对，复用
  `dispatchbridge`／`dispatch` 投递验证。
- `HQWorkspaceModels/Client/Store/Controller`：原生解码、有界 stdin 传输、异步
  交互状态与窗口生命周期。
- `HQWorkspaceView/Sidebar/Overview/Composer/Conversation/Participants/Activity`：按职责组合界面。
  `HQWorkspacePresentation`、`HQChatBubble`、`HQChatTimeline`、`HQBrandLoading` 统一阅读规则，
  复用 Theme、MarkdownBody、AgentIcons 和 HQMedallion。
- `HQResourcePage/Store/ResourcesView` 及 `HQBoardView`、`HQKnowledgeView`、
  `HQMachineView`、`HQUsageView`、`HQMemoryBar`：侧栏资料页、知识库搜索与选择、
  有界读取和档案操作。旧阅读窗控制器已移除，不再有第二个 HQ 窗口。

会话身份由 agent 类型、配置家目录 ID、session ID 组成。位置和名称只是展示
信息。修改命令从 stdin 接受一个严格 JSON 对象，正文不经 shell 拼接，也不进入
进程参数。相同 ID 和正文的重试收敛到同一记录；更换意图则拒绝。事项修改携带
版本号，旧窗口不能覆盖别人已完成的调整。

`spawn --matter ID` 在启动前核实有效事项，将明确的事项 ID 写入现有派发台账。
只有派发窗格出现匹配已保存 session 身份或本次派发精确 nonce 的绑定后，才确认会话关联。
此前 JSON 回执为 `pending-binding`，由现有 serve 快速循环继续核对。失败派发
不关联；另一个事项不能靠同名任务复用上次未投递的执行窗口。结构化 `report`
只接受当前 HQ pane 的调用。v55 托管章程说明 ID、分事项汇报与明确完成判断；
开发过程不会改写正在运行的 HQ 私人记录。

## 4. 送达与失败处理

创建事项和保存第一条指令在同一事务完成。投递先认领已保存消息，再操作输入；
进程锁覆盖整个输入尝试。粘贴及每次回车均复用草稿和状态保护，并核对 HQ 身份。
忙碌、离线、等输入、有草稿时保持待送达。serve 仅重试安全暂缓的指令，不会
自动重发未确认或已经提交的指令。结束事项会暂停其待送达指令，重新跟进后可以
继续；合并后尚未投递的上下文沿记录的关系指向目标事项。

回执区分待送达、正在确认、已送达、进入队列、未确认和已撤回。回执只说明传输，
不代表目标完成。认领后进程丢失或粘贴后发生失败，保留正文并标为未确认；用户
明确接受可能重复执行后，才可重发。只允许在尝试前撤回。HQ 结果、Stop、空闲
不自动完成事项，必须明确判断目标达成。工作台不替用户回答终端权限菜单，也
不干预 HQ 轮换；这些情况继续使用终端入口。

`workspace/records.json` 为私有文件（0600），用文件锁串行修改，并原子替换、
同步到磁盘。写入及持久化失败会明确报告。消息、事项 ID 和操作序号关联操作与
回执，现有派发、诊断记录仍保留各自的审计来源。整份 HQ 备份包括工作台记录；
恢复时先把待送达、正在提交、已排队的指令改为未确认，防止自动执行旧指令。
知识库的选择性迁移不包含这些操作记录。

## 5. 边界与验收

工作台消息按序号分页，每页 60 条。关联会话是所选时段内最近最多 200 轮的
预览。全局 HQ 原始历史复用现有 300 轮解析、字节预算及前序会话链读取，最多
请求 20 个前序会话。原始回复超过 256 KiB、来源单轮超过 512 KiB 时保留在
原始记录，并明确提示当前未载入全文；来源对话响应预算为 2 MiB，原生传输
超过 8 MiB 则报错。运行记录包括最近 200 条工作台操作与近七天最近 200 条
相关事件，涵盖接收、结束、失败、观察、派发、知识和轮换。来源失败与送达
不确定会明确显示。这些预览不是完整取证导出，也不会推断历史事项归属。

测试使用隔离数据、模拟投递和 CLI 客户端。原生宿主布局、绘制检查与实际应用、
VoiceOver 验收分开记录。当前 HQ 命令仍依赖现有客户端身份映射；新增层复用
前台 agent、配置、位置和回合核对，没有虚构独占客户端检测能力。当前链接不
匹配或有歧义时拒绝跳转。后续手机、Web 适配须执行 owner 权限规则并复用此
数据模型，不能复制一套推测规则。

空闲刷新先比较核心数据与来源版本，未变化时不反复解析历史，公开回复变化仍会
实时读取。原生命令修改与投递分别排队，回执等待不占用 serve 快速监控循环。
输入框复用截图工具的原生多行组件，包括输入法与显式发送处理。

工作台投递、自动唤醒、轮换和启动简报共用 `internal/hqinput` 非阻塞输入锁。通道争用时保留
已保存的队列，不互相覆盖。启动简报保留现有非强制投递规则，争用时明确报告
未送达。轮换拿到锁后重读持久化回执，过期的未投递快照不能再次发送重置。
人工输入仍由既有草稿与提交验证保护。

## 6. 已有工作的登记

首次打开时，旧态势板和对话可能有内容，事项台账却尚未建立。读取不会从 Markdown
或窗格猜测目标，也不迁移个人记录。空总览说明这一状态，可查看交接快照或准备一条
可编辑的全局整理请求；准备不等于发送。当前事项和全局草稿均保留，全局已有内容时
显示原稿并提示，不覆盖。

v56 章程要求 HQ 启动时核对现状，并维护各指令渠道中的持续目标。HQ 核实仍需跟进
的工作（限用户允许跟进的范围，未开启 HQ 跟进的原生会话不纳入）、复用已有 ID，已交代过的任务通过仅限 HQ 的 `register` 入账。登记一次性
保存明确状态、评估、结构化来源和一条 HQ 汇报，不新增用户指令、送达或会话关联。
重试比较原始登记字段，不重置后续改名、状态和进展；参数冲突与写盘失败明确报错。
详情中可展开来源引用，引用只作文本展示。会话仍须按真实身份和时段单独关联。
这是由 HQ 核实的登记流程，不是自动解析态势板；也不能从章程更新推断正在运行的
HQ 已经读取了新规则。

## 7. Mac 统一入口

菜单栏横幅的总览图标打开总览，知识库、机器、用量入口选中同一工作台的对应页面。
报告中的“交接快照”行保留原板保存时间，直接打开快照。
直接打开 HQ 时保留当前选择。总览和资料页不显示指令输入框，数据层也拒绝从这些
页面发送；全局对话、事项和新任务的草稿均在切换后保留。

知识库保留搜索和随窗口调整的列表／正文分栏。“HQ 档案”提供导出与导入，
导入仍可选择恢复备份、从另一台 Mac 迁移、继续核对暂存内容。大小、本地
快照、保护状态和最近导出信息放在档案标签的提示中。迁移仍须逐项核对，
不导入旧机器的态势板和工作台运行记录。

仅当前资料页每 20 秒轮询一次，沿用有界 CLI 读取，并按页面防止请求重叠。
离开资料页、关闭或遮挡工作台时停止定时器；已开始的读取可完成到各自缓存。
失败保留有效内容并提供重试。档案元数据改为后台读取。原生布局／AX 模拟
验证与实际 VoiceOver 语音验收分别记录，测试通过不代表现场读屏通过。

## 8. 读取反馈

首次读取使用呼吸渐变的 gtmux 标记和简短提示，不提前显示“没有对话”或“HQ 未运行”。
完成后才显示真实内容或可重试的错误。对话、运行记录、资料页和关联会话原文共用这一规则。
刷新时保留已读内容，用小号品牌标记提示，侧栏不会因轮询增减一行。系统开启“减少动态效果”
时标记保持静止。来源选择和代次校验继续防止迟到响应串页；页面加载与 agent 运行状态不同。
