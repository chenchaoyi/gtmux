# gtmux 状态存储生命周期

[English](state-storage-lifecycle.md)

`~/.config/gtmux/` 和 `~/.local/share/gtmux/` 是 gtmux 管理的配置与数据根。
CLI、Agent hook、本机服务、桌面组件和恢复工具共用这套路径合同。项目源码与交付放在项目存储，
构建产物和原始证据放在任务临时目录。HQ 协作笔记保留结果摘要和证据引用。
参见[源码路径合同](../../internal/state/state.go)和[交付留存规则](hq-storage-recovery.zh.md#交付材料)。

## 各类数据保护什么

| 现有位置 | 谁写、谁读 | 保留与恢复 |
| --- | --- | --- |
| 配置、知识、HQ 记录、设备权限和外部控制同意记录 | 配置与 HQ 入口写入，服务、恢复及授权路径读取。 | 保留现行记录和已验证恢复点。权限修改或记录退役走各自入口。替换前先在隔离目标试恢复。 |
| 服务和 Agent 状态、pane 标记、客户端登记、套接字链接、现行协调锁 | Hook、Agent、服务和桌面组件写入，雷达、恢复和维护探针读取。 | 由各自程序判断过期与重建。还有写入方能打开的锁需要保留。计量与清理时检查链接和套接字本身。 [私有写入边界](private-storage.zh.md) |
| `participant-profiles/` | Hook 写入观察，资料读取方合并旧快照与 `v2/` 观察。 | 兼容读取仍在使用时保留两代 JSON。`v2/locks/` 按需创建，最多 256 个锁路径。资料数量可以超过 256。分片正在被其他写入方持有时，本次观察更新会跳过，hook 的正常流程继续。 [资料写入源码](../../internal/agentprofile/observe.go) |
| `terminal-input/`、`relay/`、HQ 提醒账本及恢复与防重放记录 | 发送、领取、回执与对账进程共享请求 ID、领取记录、回执与游标。 | 保留在途、未决、未知、状态不一致和可重试的记录。回执、收件箱状态及实际处理证据各有用途。压缩前核实终态、恢复读回以及按原 ID 查询。 [输入恢复](input-spool-cutover-recovery.zh.md) |
| 上传暂存、日志、渲染缓存 | HTTP、CLI 和界面组件写入，输入交付、诊断和界面按各自需要读取。 | 按所属程序的容量与时间上限回收。`artifacts/` 的受管附件有引用和撤销规则。图标缓存可重建，特定故障日志和已接受的附件可能是唯一记录。 [上传与日志维护](../../internal/hq/diskhygiene.go) · [附件存储](../../internal/artifact/store.go) |
| `hq-snapshots/` 与旧发行、上架、报告、评审目录 | HQ 管理自身恢复点，项目维护者负责发行和验收材料。 | 新恢复点成功发布并验证后，按原备份规则淘汰受管点。旧恢复包和项目材料要由所有者核对独有价值与实际恢复路径。 [HQ 恢复](hq-storage-recovery.zh.md) |

Doctor 的存储汇总口径是逻辑字节。磁盘审计还应单列分配字节和目录项数，通过设备和 inode
对硬链接去重，并记下扫描期间变动的路径和权限错误。APFS 的卷共享容量，扫描前后的余量也会受
其他进程写入和卷分配影响。用途不明的条目继续留在盘点中，等读写方和恢复影响有证据后再处理。
[Doctor 存储投影](../../internal/app/doctor_storage.go)

## 新存储的目录和命名

按以下边界设计新存储。既有路径合同由每个子系统按自己的迁移流程维护。

- 配置、规则和耐久 HQ 记录归 gtmux 配置树。凭据沿用既有授权仓和恢复方式。
- 需要长期写盘的子系统在数据根使用稳定目录。读者需要兼容两代格式时，在子系统下使用版本子目录。
  例如 `participant-profiles/v2/` 有独立的新版 JSON 和有上限的 `locks/`，旧观察仍在旧位置。
  同一个子系统的账本、临时协调和恢复点分别有自己的目录。
- 文件名使用已有的稳定业务身份，例如请求 ID 或数据代次。高基数存储使用有界锁池。已结算数据归并前
  校验兼容与恢复。目录的保留策略由拥有读写协议的子系统负责。
- 需要留存的项目交付放入项目目录，以发行版本或事项命名。交接写清确切源版本、容量预算、复核人和日期。
  替换件仍在验证时保留当前与上一版的恢复路径。拟退役原件时先核验目标副本并在隔离目标验证恢复。
  [留存清单校验](hq-storage-recovery.zh.md#交付材料)

## 盘点、清理与迁移

`gtmux doctor --json` 可只读检查。处理空的旧参与者锁时，先升级或停用所有旧写入 hook，等执行中的
旧 hook 结束，再运行 `gtmux doctor --prune-profile-locks` 并按提示在终端确认。命令检查名称、文件属性
和 inode，用非阻塞锁跳过仍被持有的文件。执行后用 doctor 再看剩余数量和服务健康。新版分片锁即便暂时空闲
也要保留路径，避免并发打开者用不同 inode 上锁。
[CLI 文档](../cli.zh.md) · [清理实现](../../internal/state/profilelocks.go)

对未来迁移或额外删除，先记录实际写入进程、读者、所有者和准确范围，再申请授权。核对路径归属、设备和 inode、
句柄、未决请求、依赖与恢复要求。改变入口前校验暂存副本及散列，并实际试恢复。共享队列或锁的切换要停接、
排空、验证旧写入方退出、耐久发布代次，并验混合版本、崩溃恢复与回退。归属或恢复链未核实的条目继续保全。
[输入队列切换与恢复](input-spool-cutover-recovery.zh.md)

## 数据目录分组

`gtmux doctor --storage-layout` 查看已知存储、分组目标和非活动位置。现有平铺安装沿用原布局。选择分组后，相关数据使用 `layout-v2/` 下的这些目录。

| 分组 | 内容 |
| --- | --- |
| `panes/` | 回合状态、忙闲采样、目标和窗格外观标记 |
| `clients/` | 原生观察和截图请求 |
| `service/` | 自动清扫、资源与隧道状态标记 |
| `sessions/` | 恢复记录、参与者资料、对话观察和外部会话授权 |
| `usage/` | 用量、模型和限额 |
| `hq/` | HQ 台账、知识和维护记录 |
| `inbox/` | Relay 和派发台账 |
| `events/` | 当前与上一代轮转事件及序号 |
| `backups/` | HQ 快照和导出回执 |

流程分组在 v2 基础上新增 `layout-v3/hq/wake/`，下面按投递队列、提交与恢复、送达核实、共享协调分组。登记过的全局锁归入 `locks/leases/`。HQ 投递协议锁随对应目录移动，启动时用的数据布局锁继续使用固定入口。待证的唤醒原件与领取凭证可以指向同一个 inode，迁移按目录移动，保留两个原名之间的关系。终端输入队列、桌面入口、套接字和附件地址各自沿用已有协议。

Doctor 界面和实际读写使用同一份路径表。可重建缓存中符合格式、只有一个链接且超过 24 小时的私有写入暂存会列入清理计划。清理前核对预览过的对象身份，完成后报告实际数量。上传目录提供盘点，便于先核对现有附件引用。

### 离线迁移

把迁移安排在重启后、打开或恢复 tmux 之前。从独立终端运行 `gtmux doctor --fix`。在 macOS 上，先在系统设置关闭菜单栏 App 的登录启动并退出 App。旧安装器如仍有 `com.gtmux.menubar` LaunchAgent，也须卸载并停用。Doctor 会指出仍在运行的 tmux 或 gtmux 进程。自定义服务、改名的程序和旧 hook 仍需核查。在使用 systemd 的系统上，先停止并禁用用户服务、取消待启动或待重启任务，再执行离线迁移。

用户确认后，Doctor 在远程配置锁内重新核对设置。它会校验已安装和已加载的服务定义，记录原文件身份和哪些作业已加载，再在文件仍位于原路径时卸载作业。等现有写入方释放存储锁后，Doctor 先写入持久保护记录，再暂移服务文件。暂移期间，旧版 CLI 会提示存储暂不可用，包括修改远程访问和维护目录布局。launchd 原有设置和缺省状态都保留。

Doctor 先持久化布局日志并归还原文件，再解除保护，恢复仍符合当前设置的原有作业。若旧版 CLI 在保护生效前或解除后成功关闭了远程访问，Doctor 会保留这个结果。迁移、服务恢复或清理中断后，重跑原命令即可继续。存储路径尚未移动时，可以撤回这次迁移。如果服务由自定义安装目录中的 CLI 注册，请用同一份已验证的 `gtmux` 运行 Doctor。

迁移先取得固定布局锁的独占权限，记录方案并复查写入方，再用同卷排他重命名。流程分组启用后保留兼容标记和迁移记录，旧版 CLI 会沿原入口拒绝访问，直至按流程回退。

中断后普通命令会暂缓。用 `--storage-layout` 查看已迁移、待迁移和冲突。在恢复 tmux 前的维护窗口内，`gtmux doctor --fix` 会按已核记录继续。每个原件必须在唯一位置和原身份一致。目标占位、证据不完整、符号链接或他人所有的对象会阻止继续，原件保留在原处。

回退软件版本前，沿用同样的维护步骤，执行 `gtmux doctor --flatten-storage`。分组期间新增的原件也会回到平铺路径，发现另一份同名对象时会拒绝覆盖。如果原子写入中断，在分组目录下留下符合格式的私有暂存文件，回退会把原件保全在 `layout-recovery/<id>/`。暂存文件不会成为活动状态。无法识别的条目仍需核查。安装后不会自动移动已有数据。
