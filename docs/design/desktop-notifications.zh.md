# Mac 桌面通知

Hook 向本机私有队列写入请求，菜单栏应用再提交原生通知给 macOS。进入队列、系统接受、用户看见横幅是三回事。成功回执只写“已提交给 macOS”；是否展示、是否有声音，仍由专注模式、系统授权、横幅样式和声音设置决定。

## 时机与形式

- 保留系统横幅和通知中心，以及 hook 提供的会话名、窗格和 agent 信息，不另做悬浮提示窗。
- 确实需要批准、回答或审阅计划时，以普通优先级请求声音提醒。遵循专注模式，不把每次等待都标成“时效性通知”。
- 一轮成功结束时静音提醒，写“本轮已结束”，不声称整个任务已完成。取消和失败不冒充成功。本轮不另加错误通知类别。
- 保留已有 hook 规则：正在查看该会话时不提醒；HQ 的例行结束保持静默；已经处理的等待提示撤回。不为工作中、进度或工具调用增加提醒，也不补播旧积压。
- 原有回复、跳转保留当前目标。测试通知没有会话目标或回复、跳转动作，不会向 agent 输入内容。

队列中的每个独立文件都是一次事件，同一 pane 后续再次完成也应处理。原生通知的固定标识用于替换该 pane/类别上一条通知，不用于永久去重。提交失败不能阻断后续事件。先监听目录，再读取队列；等待授权结果后再处理，并在正常轮询中补读。菜单栏图标因空闲而隐藏时，仍要处理通知与撤回。超过 30 秒的请求继续丢弃。

## 紧凑诊断

偏好设置将“桌面通知”开关与说明放在同一行，下方集中展示系统权限和“测试通知”。测试结果紧邻按钮，“系统设置…”紧邻权限状态。“标签标记”单独放在“终端提示”分组；声音和专注模式说明放在组尾，不再各占一条设置行。打开设置、从系统设置返回和正常轮询时更新。不会自动更改系统设置，也不声称专注模式已关闭。测试回执只说明系统接受了请求，是否出现横幅需用户查看横幅或通知中心。

这部分只控制 Mac 本机队列。手机、iPad 的 APNs、外部对话的通知授权和浏览器行为沿用现有规则。由服务端轮询并核对授权的原生 Codex/DSH 对话，不会因为这次修复而被擅自接入 hook 本机队列。

## 证据与边界

测试注入模拟通知中心，使用临时目录，验证连续多轮、失败后恢复、启动和权限切换期间的竞态、撤回已处理的等待，以及过期、关闭、拒绝权限和无会话目标的测试请求。它们不证明真实系统授权、专注模式、横幅外观或 VoiceOver 已验收。

设计依据 Apple 的[简洁且有用的通知建议](https://developer.apple.com/design/human-interface-guidelines/notifications)、[读取当前授权与通知功能设置](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/getnotificationsettings(completionhandler:))和[本地通知请求 API](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/add(_:withcompletionhandler:))。

未确认的原生控制端不等于 ChatGPT Desktop。手机通知引导用户回到原应用，不猜来源，也不给不可用的终端回复按钮。只有明确识别为 ChatGPT Desktop 的来源才使用该名称。
