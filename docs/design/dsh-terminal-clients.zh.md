# DeepSeek Harness 终端客户端

会话继续使用 `dsh`、DeepSeek Harness 名称和官方鲸鱼图标。终端客户端只是内部适配器，
不会成为另一种 agent。首个适配器针对 dst 0.16.1 的 DSH 后端和 DSH v4 会话契约。
dst 的其他后端不会被认成 DSH；Web 对话沿用外部只读历史和明确授权后跟进的机制。

## 绑定与输入

`internal/agentclient` 将有效期五秒的私有原生绑定，与 DSH 数据目录、精确根会话、tmux
服务代际、进程祖先、dst 前台注入注册表、挂载会话表和原生注册表中的实时 v4 根会话逐项核对。
新会话可以先有实时身份、后有首条历史文件；已有文件损坏或代际不受支持时仍拒绝。后台挂载本身不能选择
pane；冲突或过期即撤销输入能力。雷达和对话读取使用当前绑定，同一会话不再重复显示
为外部对话。各端消费同一份核心数据，复用已有官方图标。

原生桥接组件只声明一项 `commands.invoke` 能力。`gtmux-send` 命令拿到真实的
`CommandInvocation.agent`，核对数据目录、会话、进程实例及绑定，再通过原生 `followup`
提交带消息身份的用户文本，不创建第二个会话写入者或模型代理。命令携带 128 位随机令牌，
正文留在最大 1 MiB 的私有请求文件中，不放入 shell 参数。先独占领取，再入队；只有目标
一致的原生回执才能证明接收，不代表模型已执行或任务完成。领取后结果不明时不自动重投。
完成请求的重试记录保留 24 小时；未解决的请求保留，到 4,096 个文件的上限后停止新输入。
过期且未领取的正文在下一次发送时清理。

既有投递流程继续保护草稿，适配器还要求粘贴和按 Enter 时都处于 dst 紧凑输入框的插入
模式。菜单、提问、展开编辑器和 Vim 普通模式均拒绝发送。令牌必须完整出现在输入框中，
窄窗口折行可能拒绝投递。手机发送继续受身份、分享范围和同意门控制，不覆盖草稿。
Web 历史没有原生输入能力；CLI `--no-enter` 只是放入草稿，不会声称已被原生接收。

## 消息证据与审阅

异步核对器为已核验的前台会话保留增量读取位置，最多 16 个读取器，每轮最多 100 条公开
消息或 4,096 条新源记录；压缩帧沿用 DSH 读取器的大小限制。日志去重只增量索引有限数量
的消息键，不会每次请求都全量解析生命周期日志。只提取公开用户文本和已组装的助手文本，
排除思考、注入、工具结果、替换与重放副本，因此源序号存在间隔可以是正常现象。

`ConversationMessage` 提供消息身份和简短公开摘要；`transcript --messages` 分页读取公开
正文。读取和消费 HQ 事件都不等于审阅；`--review-through` 才是明确的本地声明，只能推进
到本页返回的消息。HQ 章程会教这一区别。源读取失败、替换或观察到截断时产生
`ConversationGap`，替换还会重置审阅覆盖。保留数量、未观察到的重写和缺失源材料意味着
不能保证完整历史或严格只出现一次。切换到终端对话不会自动纳管较早的 Web 或后台区间，
可用明确的历史读取核对。不会自动批准权限，也不会新增事前审批关卡。

## 安装与验证边界

安装器写出 gtmux 自有原生模块、组件清单和启动覆盖文件。已有 dst profile 会在验证 YAML
序列后，在 `profiles/dsh-tui/cordis.patch.yml` 加入自有标记段，其他文本与自定义标签原样
保留，并按内容生成备份。卸载只移除该段和自有文件；YAML 歧义、文件归属不明或配置文件
为符号链接时拒绝修改。非空行内根数组需先手动改为块序列。gtmux 不会安装或升级第三方
npm 包。

普通 `dst --backend dsh` 即加载 profile 桥接。`spawn --agent dsh` 选择声明的终端客户端，关闭首页并明确当前工作目录，让首条任务同时等待聊天输入框与原生接收端。新 pane 直接启动客户端，避免 shell 初始化吞掉启动按键，并明确传入配置的数据目录；
终端恢复记录限定原有数据目录和客户端；Web 会话仍不能 adopt。模型在 dst 中选择，此
适配器拒绝通用 `spawn --model` 和一次性执行。

Doctor 分开报告文件及 profile 配置、实时绑定和可撤销输入权限，不重启现有工作。
作者构造数据测试通过或组件成功加载，不代表真实 TUI 投递验收通过；交付报告需分别说明
屏幕验证、原生入队和真实模型执行的覆盖。

接口依据：[dst v0.16.1](https://github.com/ccch1mneyyy/dsh-TUI/tree/73ff99fbed56563bf154d719effd09f9f9725349)
的前台发现、组件准入和命令接口，及
[DSH 会话契约](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.2.0-rc.2/packages/core/session)。

## 终端重绘时的原生状态

已验证且接入原生生命周期事件的终端客户端，会单独保存一份原生事件状态，绑定当前
harness、数据目录、会话、pane 和客户端进程实例。开始、提问、恢复和结束 hook 决定状态；
屏幕/CPU 变化及通用 active/finished 缓存不能覆盖它。“完成时间”缓存也可能由雷达推断生成，
因此不能证明原生回合已结束。

同一个 DSH 会话的持久化历史若出现更晚的明确回合边界，可以补救漏掉的 hook。
历史的默认状态、不相关会话和更旧的边界不能覆盖原生事件。读取复用现有增量 DSH 索引，
不扫描全局事件日志。两种证据都没有时保留中性状态（`running`），不编造完成时间。
旧会话需要自然发生的 hook 或明确历史边界，不猜测补填，也不需要额外安装插件。
原生提问在界面重绘时保持等待，直到原生恢复/结束事件或更晚的明确回合边界出现。
这项能力由适配器声明，换社区客户端时 harness 身份仍为 `dsh`；其他接入保留各自文档说明的回退。
已跟踪但仍卡在输入框中的未投递目标，继续使用独立的投递等待判断。
