# 内置演示的覆盖范围

配对页的「看看演示」使用正式的手机或 iPad 页面，数据来自 `ui/demoClient.ts`。
目前没有单独部署的公开 demo server，App Store 审核也走内置演示。
`e2e/fake-serve` 是本地测试服务；`seedDemo` 复用同一份数据和交互脚本，用于截图与 HTTP 检查。

## 覆盖内容

| 功能 | 演示内容 |
|---|---|
| 雷达与导航 | 手机、iPad 共用正式页面；支持数量、筛选、HQ 入口及所有窗格，含普通终端窗格 |
| 对话与终端 | 共用正式阅读组件，支持 Markdown、回复、模拟输入；批准后依次运行、完成，拒绝不会执行测试 |
| Codex | 中间回复、工具步骤，以及桌面工作会话的只读查看；不开放桌面会话输入或跟进设置 |
| HQ | 汇总、态势板、对话、派发任务和运行记录；处理权限请求后，各处状态同步更新 |
| 用量 | 额度窗口、与雷达一致的会话身份、按 agent 汇总，以及七天用量和活动记录 |
| 知识库 | 准确的主题计数、按时间排序的条目、对应正文、推广示例和双语条目 |
| 数据隔离 | 明示演示数据，不读真实输入历史、不持有服务器凭据、不发送真实指令；退出时取消未完成的模拟任务 |

样例是一台 macOS 主机，不代表 Linux 运行验收。新的 macOS HQ 工作台属于原生端；
演示使用手机、iPad 当前实际提供的 HQ 页面。

## 有意保留的边界

真实会话创建、配对与分享管理、线路切换、访问历史和推送注册依赖已配对服务器或真实设备身份，
演示不提供这些入口。知识修改会明确拒绝；切换线路也不能假报成功。
不能用演示通过来代替实际服务器管理、通知或网络恢复验收。

## 后续如何防止落后

新增客户端方法时，必须实现演示数据，或在 `NotInDemo` 明确说明为何不适用。
正式页面已经调用的方法不能排除：例如 Detail 的发送入口是 `sendResult`，演示也必须支持相应回执与重试。
窗格和用量身份从同一组会话派生，HTTP 测试服务复用同一套交互脚本，避免另外维护一套权限模拟逻辑。

`demoParity.test.ts` 检查批准与拒绝、时间稳定性、重置和取消、回执重试、计数与只读边界；
`fake-serve/demo.test.ts` 用正式 HTTP 客户端验证同源样例；
`DesktopConversationView.test.tsx` 验证演示使用正式只读页面且没有输入框。
这些检查不等于真机布局、VoiceOver、推送或实时活动验收。
