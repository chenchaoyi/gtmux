# 在会话页操作终端提示

聊天记录只保存消息，临时授权、提问和选择器可能只存在于终端画面。受管理的 tmux 会话等待用户时，交互卡即使解析不出编号选项也会保留。没有识别到等待时，用户可以手动打开“交互”；这不会改变 Agent 状态。

## 信息来源与输入

`GET /api/interaction?id=%N` 通过核心 tmux 适配器读取当前可见画面，不读取滚动历史。去掉终端控制序列后，仅保留末 80 行、16,000 个 Unicode 字符，并明确标注截断。这是实时观察，与聊天记录分开展示，不声称能理解所有 Agent 的提问格式。

编号按钮同时要求 Agent 自己发出了待回复信号，以及公共解析器确认当前画面确有可直接用数字回应的菜单。复杂布局、多选、启动选择器、被截断的画面和不安全的标签不产生数字按钮。不猜“同意／始终同意／拒绝”，也不猜默认项。状态仍优先依赖专用 Hook；画面用来提供操作上下文与兜底，不替代状态判断。

手机交互卡与输入框共享同一个按键控制器。方向键、空格、回车、完整按键目录以及“查看问题”等上下文动作，复用已有能力目录、目标绑定和发送结果队列。每次只发送明确的一次按键或数字，不附带回车。结果未确认时停止后续按键，由用户明确处理，不自动重放。旧服务器仍可使用原有按键与选项，同时提示暂未提供当前画面。

## 各端与布局

- iPhone／iPad：交互卡独立于聊天滚动区域，内容限高、纵向滚动，终端文字可横向检查；支持收起，手动打开时可关闭。等待提示收起后仍可找到，可直接打开会话输入框。全屏阅读时仍保留这类需要用户处理的交互。
- Web：相同的实时画面、只读限制与兜底按键；Chat 内也能使用稳定的共享输入框，切换显示模式保留已输入文字。交互卡不随聊天历史被卷走。
- CLI、菜单栏：保留既有选项与终端操作，不新增另一套解析器或 CLI 命令。

离开等待／手动查看状态时停止请求，后台暂停；其他 pane 或服务器的迟到结果不能覆盖当前内容。读取失败会清除旧选项并提供重试，不删除聊天记录。轮询画面不等于菜单在点击前不会变化；实际输入仍由服务器权限和目标绑定校验。

没有可靠 tmux 输入路径的外部会话继续只读。分享链接只能读取授权 pane，能看不等于能输入。源代码测试仅使用合成提示，不包含真实用户对话、设备标识或截图。合成界面检查、原生编译、独立审查、实体设备与 VoiceOver 验收分别记录。
