# 输入队列切换的排空和恢复

本文补充共享输入队列的切换设计。旧版 Go 的 pathname 写入在原子交换后会失败，但交换不会撤销已经打开的文件或目录 fd。生产仍用 4,096 槽和原 v1 文件格式。

## 先停写再换目录

1. 阻止新发送进入旧 Go 和旧 DSH。拒绝期间返回可辨认的维护状态，未确认的客户端操作不自动换 ID 重试。
2. 由掌握入口和进程归属的协调者等在途操作落盘退出，确认旧进程无法再取得或持有队列和暂存文件 fd。普通句柄列表仅作佐证，不能证明所有入口已关闭。旧 Go 回执和旧 DSH 不会遵守新加的租约，不能用新锁代替旧写入方本身的静止条件。
3. 写受管的切换记录，校验旧目录与普通文件标记的设备、inode、类型和归属。两路径用原子交换，保留旧目录 inode。Go 和新 DSH 要通过同一阶段与身份闸门。只检查一次启动路径的接收器可能已经注册命令，因此在每次提交前还应复核阶段与目录。调用检查与写入之间仍需协调停写。
4. 初次放行发生在交换后、激活记录成功持久化之后。切换记录包含已准备、已激活或回退中阶段和绑定的目录及标记身份。实例发现或系统启动还未确认状态时保持拒写。异常数据保留原件。

## 中断后的恢复

| 持久阶段 | 观察到的路径 | 恢复动作 |
| --- | --- | --- |
| 已准备 | v1 仍在旧路径，标记在新路径 | 可撤销准备，回到经校验的 v1 |
| 已准备 | 目录和标记已交换 | 仅在停写仍成立、从未激活时，原子交换回去 |
| 回退中 | v1 已恢复，标记还在或已删除 | 继续清理本次私有事务的标记和记录并校验 v1 |
| 已激活 | 新路径为原目录，旧路径为绑定标记 | 重启原地继续新布局，保留在新代完成和未确认的状态 |
| 缺失、损坏或身份矛盾 | 任意 | 暂停发送，保留两路径和证据，人工核对 |

已激活后不能自动恢复旧 Go 写入权。若要退回旧版本，重新排空、保存和对账，再验证旧容量足以承载现有记录，并核实旧版的重放和回执约束。进程级故障注入只能证明已观察到文件系统状态的恢复，整机断电、服务顺序和旧真实进程清单需要单独验收。

## 容量建议

保留 4,096 生产默认。此前 4,515 的单一测样在 6,144 试验配置下通过，腾出 1,629 个按预留计的槽。旧试验改了常量，派生扫描上限也随之从 8,192 变为 12,288。样本只有 3,168 个实际目录项，因此它没有验证扫描上限或长期高负载。优先设计本机所有者单独配置且有上界的过渡容量，保持扫描上限独立，验证条目、配置错误、字节占用和失压回收后再讨论默认值。本轮没有实现配置或调整默认。

待选范围包括实际停写入口、维护窗口、与 DSH 接收器的升级顺序、重启守护职责和绝对容量上界。真实有在途写入方时不执行试验步骤。

## 隔离验证结论

- macOS 真实目录交换后，提前打开的目录 fd 能在迁走的 inode 下创建文件，提前打开的普通文件 fd 也能继续写。夹具的排空信号只有在受追踪写入者写完旧回执、关闭 fd 并退出后才放行。同一夹具的互斥约束不约束现行旧 Go 或 DSH。
- 交换前、交换后未激活、回退中途三种进程中断恢复了原目录 inode 和所有原 v1 文件字节。激活后重启保留新版接收器写成的回执，并拒绝自动换回。缺失、损坏或目录身份不匹配均保持拒写和原件。
- 基于 v1.0.185 接收器的测试覆盖启动注册和真实命令处理。切换前拒绝注册，恢复 v1 后能在原路径结算，激活后在新路径写回执且同 ID 只提交一次。挂载后发现日志身份变化，命令及发送就绪声明都会拒绝，原待发保持。使用模拟 tmux 和 agent，不读取真实会话。首次恢复 v1 后 DSH 未注册的尝试保留，随后同源新私有环境全通过；首次失败原因未确定。

## 生产接入检查

- `internal/app/send.go` 的 CLI 和服务发送入口要共享停接入状态。原生 Codex 写入经 `internal/dispatchbridge/codexinput.go`，DSH 经 `internal/dispatchbridge/dispatchbridge.go` 的 `WrapIO` 和接收器命令。升级协调要覆盖已加载的旧 DSH 和仍能启动的旧 CLI。先证明各入口都停止取得新写入权限，才可把实际进程退出和回执对账当作交换前置。
- Go 与 DSH 需实现同一格式的激活记录，并在发件准备、领取、结算和接收器就绪时核对同一代目录。隔离脚本中只有 DSH 选择器接入了真实接收器，Go 侧还没有接入生产代码。下一验收应覆盖两个语言实现的同一状态用例，包含断电、启动先后和升级失败的明确恢复动作。
