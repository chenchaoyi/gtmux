# 桌面会话跟进

[English](desktop-follow.md) · **中文**

检测到 ChatGPT 桌面版 Codex 会话，只让其状态可见。是否交给 HQ 跟进，由用户逐个会话决定。

## 权限

| 模式／选项 | 效果 |
|---|---|
| 仅显示状态（默认） | 单列于「桌面应用」；不计入管理总数、HQ 未读／摘要、通知、实时活动或内容采集 |
| HQ 跟进 | 读取对话、分析和汇报；随后一个 Unix 秒之后的生命周期事件进入 HQ 关注范围 |
| 接收通知（初始关闭） | 允许此会话后续的待处理／完成通知；仍在 ChatGPT 桌面版继续对话 |
| 知识采集（初始关闭） | 从授权后的活动采集可复用经验；HQ 核实线索后才写入知识库 |
| 停止跟进 | 结束观察并关闭两项设置；保留已有记录和知识 |

跟进不会赋予 gtmux 桌面输入、批准、跳转或转入 tmux 能力。策略仅适用于 native Codex 会话，
且必须由日志 `session_meta.originator` 精确确认（`codex_work_desktop`／`Codex Desktop`），
不依据工作目录、标题或日志的 `source`。终端 Codex 和其他 agent 不变。

## 权威与存储

策略由 `internal/sessionpolicy` 管理，界面只消费它。`~/.local/share/gtmux/session-follow/`
中的每份文档包含已确认的会话 ID、三项权限、授权时间、版本号和独立的知识授权区间版本号。文件名对 agent／ID 做哈希，
目录私有，写入加锁、同步并原子替换。没有设置时默认仅显示状态；读取损坏或失败时关闭权限并
记录诊断，保存失败返回错误。保存须匹配读取的版本号，旧设备收到冲突回执。

CLI `gtmux follow`、菜单栏设置窗口和已配对的手机／iPad 修改同一份文档。HTTP 接口在调用
写入器前拒绝访客。成功修改会追加不含对话内容的 `gtmux:audit:session-follow` 回执。
策略位于 HQ 档案之外：换机迁移不能自动重新授权旧 Mac 上的会话。HQ 指引明确禁止自行开启跟进。

## 采集边界

- 雷达仍读取身份和状态元数据。默认桌面会话在摘要的对话内容读取器及用量汇总运行前被排除。
- 生命周期记录带确认的客户端及 `knowledge_allowed`，原始元数据保留用于诊断。HQ 未读、
  默认拉取、待处理自检和 HQ 历史共用观察门禁；显式 `events --all` 仍是诊断视图。
- 更新中心从管理汇总和通知中排除仅显示状态的会话。开启设置不重放当前待处理／完成状态。
  通知发送前再次检查权限，以尊重撤销；native 通知使用会话维度的折叠标识。
- 知识采集先检查元数据头，再调用对话读取器。授权从随后一个 Unix 秒开始，保守排除保存
  当秒的活动。所有内容记录（包括 shell 错误）均受时间边界限制。新一轮授权（包括同秒停止后再次开启）重置偏移和上下文，
  避免之前的 assistant 回复进入新线索。增量上下文保留身份；旧 Codex 台账从元数据头补回身份，
  不重放旧消息。缺少 ordinal 的 Codex 记录以文件身份和字节偏移生成稳定、互不冲突的来源标识。
- 已有待整理线索和已入库知识保留，不删除或静默改写。当前只允许观察的事件，不构成入库授权。

## 界面与验证

CLI 和 Web 提供诊断可见性，CLI 可修改设置。Web 单列桌面分组和策略标记，不向访客开放设置。
Mac、手机和 iPad 提供按会话设置的表单：已保存状态、明确选项、随草稿变化的单个保存操作，
以及失败／冲突反馈。iOS 上先等会话菜单完成原生关闭，再打开设置表单；切换会话会取消待执行的弹窗交接。iPad 与手机共用组件，限制宽度并适配安全区域。

只有桌面会话时，列表与跟进入口仍可见；列表显示不依赖管理总数。顶部各状态计数排除仅显示状态的桌面会话。

回归覆盖：`internal/sessionpolicy/policy_test.go`（默认、逐 ID、撤销、冲突、损坏和 I/O 失败）、
`internal/radar/desktop_policy_test.go`（协议字段与 HQ 身份）、HQ 未读／拉取、服务器权限与
通知中心、知识采集授权、Swift `SessionFollowTests`，以及手机 `SessionFollowSheet.test.tsx`
（草稿、回执、冲突、重复点击和晚到响应）。VoiceOver 与手机／iPad 真机布局验收仍需连接且
解锁的设备；组件自动化测试不代表已完成真机验收。

## 构建检查说明

本 PR 的 CI 自动选用了 Go 1.27.2，但固定的 Staticcheck v0.8.1 无法解析其版本 5 的导出数据。
因此 `make lint` 仅将此分析器固定到 Go 1.27.1，CI 也调用同一目标。编译、race 测试及漏洞扫描
仍使用 CI 当前的 Go 补丁版本。Staticcheck 支持新格式后应重新评估这一固定版本。
工具链选择使用 Go 官方文档中的 [GOTOOLCHAIN 机制](https://go.dev/doc/toolchain)。
