# Go 和 DSH 输入队列启动门禁

## 共享布局

Go 和 DSH 各自校验同一份受管记录。缺少切换记录且没有新目录时，可以从原 v1 队列启动，也可以在干净用户目录下创建 v1。原路径如果是普通标记文件、链接或其他不兼容对象，不能当作空队列重建。

有效的 `terminal-input-cutover.json` 在 `active` 阶段绑定 `terminal-input-v2` 的设备和 inode、原位置普通标记的设备和 inode，以及两者共同的代次。记录和标记必须是当前用户私有的单链接普通文件。无效、未激活、身份不匹配或记录丢失的切换布局不给出可写路径。

Go 的准备、领取、结算绑定实际有效的队列代次和目录身份。读取已结算凭据不会获得新的发送权。重新准备相同 ID 仍使用原索引和回执；没有可信终态的领取继续阻止重放。代次绑定只在内存中，与旧记录比较时仅比较原 v1 字段。DSH 在注册时选定布局，更新就绪及执行命令前复查。Go 在激活的布局中仅接受同代的 DSH 就绪声明。

`agentclient.InputDir` 是等效的只读预检入口。它返回当前可解析的目录，在不确定时返回空，预检本身不创建目录或锁。这个结果只评估磁盘布局，不能证明其他写入者已经停止。

## 启动和停止顺序

| 状态 | 新 Go／新 DSH | 旧 Go／旧 DSH |
| --- | --- | --- |
| 原 v1，尚未进入维护 | 使用原目录 | 原目录兼容，可继续运行 |
| 已准备、回退中或切换证据无效 | 不取得队列写入权 | 交换前必须从外部停接并排空；交换后原路径的文件标记会阻断新打开 |
| 有效激活且身份一致 | 重启后仍选择新路径；DSH 只向同代发送 | 停留在旧路径，无法通过路径打开新队列 |

停接、核对回执、关闭所有旧 fd 必须在写入准备记录及交换前完成。继续验证普通 CLI、服务器 API、已加载的旧 DSH 及维护期间能够重新启动的旧入口。进程崩溃后由负责维护的协调者复核阶段和路径；本候选只是选择或拒绝，不创建激活记录或自动回退。上一轮专门保留了换名前、未激活和回退中断的隔离验证。生产接入仍需验证断电恢复、实际进程与启动顺序。

## 容量和字节

生产仍按 4,096 个有效槽准入，扫描仍为 8,192 个目录项。已有的 6,144 槽试验与实际容量采用不同的证据：当时为 3,168 个文件预留 1,347 槽，合计 4,515，额外空余 1,629。试验中的派生扫描上限随常量升至 12,288；它没有证明扩大扫描或全局默认有收益。

确有过载且可在维护窗核清的单机可考虑有限期、仅拥有者设置的过渡额度。扫描边界应独立有界，保留在 8,192 是区分开销和准入的起始候选。还需在开通前对每项实际序列化大小、领取／索引／回执、暂存写以及磁盘余量做字节预算，不能用单请求正文 1 MiB 推导完整队列所需磁盘。低余量时应优先保证原请求结算空间，保存未知和接受凭据。过渡额度及字节预算经评审后再实现，并在超限及重启条件下验证。
