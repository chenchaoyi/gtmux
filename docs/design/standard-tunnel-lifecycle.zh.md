# Standard 隧道生命周期与自动恢复

完整状态与实施约束见[英文设计](standard-tunnel-lifecycle.md)。本设计取代旧的回收与“重建后换地址”规则。

## 用户应得到的结果

开启 Standard 常驻访问后，Mac 睡眠、网络中断、长期离线，甚至 Cloudflare 隧道实例被回收或误删，
都不应导致地址变化或手机/iPad 重新配对。Mac 恢复联网后，gtmux 自动恢复连接。
**此前被旧 bug 误删、仍保存旧设备身份和地址的设备也在修复范围内。**

旧二进制需要升级才能自动发起恢复；服务端先部署新控制面，再发布包含恢复监视器的 CLI。
配对权限与连接器 token 是两层独立凭证：恢复不会重新签发手机凭证，不会恢复已撤销的权限。
用户选择关闭、局域网或 Direct，优先于任何正在进行的自动恢复。主动清除本机身份或凭证属于重置，
系统不能猜测或自动找回原授权。

## 根因与回收规则

旧代码把 `conns_active_at == null` 当作“从未连接”。Cloudflare 用它表示当前不活跃，
包括曾经在线、刚刚断开的实例。代码还把在线连接开始时间当作长期闲置依据，因此存在两种误删路径。
先清理 DNS、再强制清空连接，也会绕过在线实例保护，或在实例删除失败时先破坏可用地址。

现场删除时间与部署中的定时任务和错误判断吻合；审计权限不足，不能声称已独立确认具体删除执行者。
私人账号信息、设备标识和事件回执不写入开源仓库。

| 提供方的最新状态 | 处理 |
| --- | --- |
| 在线、降级但仍有连接 | 无论多久都保留 |
| 曾连接、当前离线 | 仅在有效断连时间后超过 90 天回收实例 |
| 明确从未运行 | 创建超过 24 小时后才可回收 |
| 字段缺失、未知、矛盾、时间无效或接口故障 | 保留 |
| 明确已删除或 404 | 保留设备身份和地址预留，等待恢复 |

只处理有注册归属的实例，名称以 `gtmux-` 开头不足以证明归属。删除前重新读取详情，
不强制断开连接。先删除实例成功，再删除精确指向该实例的 DNS 记录；绝不依据旧列表删除新路由。
未完成的恢复也适用：按保存的 ID 或唯一操作名称核实替代实例，执行相同的闲置规则；
回收后重置操作进度，保留原设备身份与路由，回来时继续恢复。
Cloudflare 注册连接与删除并不构成跨系统原子事务，仍依赖提供方拒绝删除有在线连接的实例。

## 持久化与并发

每台设备用一个 SQLite Durable Object 串行执行开通、恢复与回收。KV 提供旧记录迁移和发现索引；
迁移后以对象持久化状态为准，不能用滞后的 KV 覆盖新记录。
固定域名属于设备身份，Cloudflare 实例 ID 可以改变。

创建前保存唯一操作名称；若创建成功但响应丢失，下一次先按该名称查找实例，避免重复创建。
创建出的 ID 立即记账，中途失败继续原操作。取得 token 并配置 ingress 后才切换 DNS。
DNS 只能指向已知旧实例或本轮新实例；不明归属的记录保留并报冲突。

只有明确已删除或 404 才允许替换。超时、TLS 错误、401/403、429、5xx、无效响应都不是删除证据。
KV 更新合并写入并通过持久 alarm 重试，避免每键每秒写入限制；不会因索引更新失败丢失恢复进度。
每天分页处理至多 100 个发现键，保存游标，下一轮继续。恢复已有设备不消耗首次开通的每 IP 额度，避免同一网络下多台受影响 Mac 互相阻塞；
仍受全局容量限制。额度统计是尽力而为的软限制；定时只读扫描最多十页账号实例来纠偏，
扫描失败或不完整不能把额度重置为零。记账写入失败不会阻塞已创建实例的恢复。

## 本机恢复与关闭优先

serve 读取 cloudflared 的已注册连接数，给予连接宽限期，再在后台发起单个恢复请求。
请求有截止时间和指数退避，最长一小时，不阻塞正常 serve。接口成功不等于实际边缘连接已恢复。

请求前快照 Standard agent、serve agent、设备身份、地址和主凭证；应用结果时取得与模式切换共用的短锁，
要求快照仍完全一致。用户关闭、切换模式、重装或重置身份后，丢弃旧请求结果。
自动恢复使用专用 `/standard/recover` 接口，旧服务端只返回 404，不能先执行旧的换地址逻辑。
主入口和备用入口共用请求截止时间；服务端必须确认恢复并返回原地址，才能应用结果。

只原子更新连接器 plist，保持 0600，保留原二进制、参数、端口、serve 进程和配对文件。
重载前持久保存配置哈希标记，成功后清除；重载失败或中途退出后仍可继续修复。
不打印 token 或 QR，不修改 Clash、VPN、解析器或无关服务。

## 回归与上线

覆盖短暂离线、长时间在线、90 天边界、未知状态、旧 bug 已误删设备、接口失败、DNS 冲突、
创建响应丢失、持久化中断、并发恢复、回收竞态、本机重载失败，以及恢复中切换 Off/局域网/Direct。
先验证 Worker 类型、真实 Workers 运行时、CLI 完整测试和构建，再部署控制面与更新 CLI。
上线验证应使用原地址和已有配对，并检查真正注册到边缘的连接；构建或 dry-run 不算生产已修复。

回滚必须保留 DO 绑定、类和恢复进度。不能恢复旧的 KV 独立写入或误删判断；出现问题时先停回收，
保留设备与地址。域名预留不在本次修复中回收或转让给他人。
