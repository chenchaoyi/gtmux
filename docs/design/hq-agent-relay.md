# Agent → HQ relay (v1)

`gtmux relay report|ask` records an agent-authored request under the gtmux state directory. The caller's live `TMUX_PANE` determines its source; tmux supplies the session and the dispatch ledger supplies the task ID. The CLI accepts a caller-supplied request ID for retry. A repeated ID with identical content returns the existing record; a changed payload is refused. The record is committed before a wake is queued. Reports stay in the ledger; blocking questions wake HQ with only the ID and source. HQ reads `gtmux relay list/show`, claims a request, then replies or closes it. The wake is a hint, not the queue.

Each JSON file has one request and its state (`pending → claimed → replied|closed`). File updates take a process lock and use rename, so concurrent CLIs cannot claim twice or expose half a record. Claims carry a lease; an expired claim can be reclaimed after HQ rotates or disappears. A reply is recorded before delivery. Delivery is retried by ID until confirmed and the source pane still belongs to its original session and pane process. The injected text is explicitly labeled as an HQ reply to an agent request, and the existing send audit marks HQ as its author. No direct agent-to-agent route exists.

The source pane may be gone, reused, or back at a shell; replies then remain visible in the ledger without being pasted into another conversation. The managed machine-knowledge block gives Claude, Codex, opencode, and Kimi a short global relay note after `gtmux knowledge sync`; newly started sessions load it. Other agent types learn the entry point from a new interactive `gtmux spawn` dispatch. Existing conversations must reload their instructions or use `gtmux relay --help`. HQ's managed playbook names the pull/claim/reply flow and the permission boundary. Requests addressed to the user cannot receive an HQ reply: the user answers in the source pane, after which HQ can close the record. HQ may relay other questions to the user, but cannot grant a user-specific permission, choose a user-reserved plan, or authorize an irreversible act. One-shot jobs have no live reply composer and remain outside the reply path in v1.
