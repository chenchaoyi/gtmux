# 完整数据收集中的 Codex 路径发现

`radar.Collection` 为一次 digest、用量请求或有顺序的检查过程持有延迟建立的路径索引。
每次调用 `Agents` 都重新采样会话状态。它不是会话缓存，不能作为服务全局单例保存。

digest 通过 `Driver.ContentIn` 读取结构化内容；关闭 Content 能力后仍不读取，
自定义和其它 agent 保留各自的读取器。内置 Codex 解析器复用原有增量加载机制，只共享
本次操作匹配到的路径。用量通过 `ForSessionScoped` 读取，继续使用原始 rollout，
保留已有字节偏移计数的文件身份，不将续写文件当成新的计数基准。

索引只记目录发现及路径匹配；日志内容、token 总量、状态、身份核验和授权仍重新读取。
下一次 Collection 会发现新建文件。HQ 的 watchdog、stuck、resolved 检查只共用路径发现，
继续按原顺序执行，并在前一步可能改变标记后重新采集会话。

独立调用的对话和用量 API 每次仍查找最新路径。额度探测缓存与每日历史目录维持各自策略；
“一次发现”的断言针对对话路径解析，不代表用量报告只能执行一次文件系统操作。
本轮没有全局跨请求缓存、协议字段或授权规则变化。

模拟测试覆盖完整收集过程的扫描次数、内容/状态/用量更新、撤销授权及计数基准文件。
变异验证分别让 digest、用量绕过索引，以及错误缓存会话行，要求对应回归测试失败。
