# Agent hook lifecycle contracts

[中文](agent-hooks.zh.md) · audited 2026-10-11. This records the eight existing hook integrations, not additional agent support. [Agent onboarding](agent-onboarding.md) remains the integration checklist.

A hook observes the agent; it must not approve tools, change prompts, block a turn, or restart a session. **A successful completion, a cancellation and a terminal error are different outcomes.** Cancellation/error clear working and waiting, retain their outcome for the independent alert poller, and do not earn a completion notification or update the latest completed pane. A subsequent real turn start resets the outcome. A tool failure is not necessarily a failed parent turn.

## Ownership and polling

Known mismatched turn_id callbacks cannot end a newer turn. Tool, permission and compaction callbacks arriving after a cancellation cannot rearm it; only an actual new prompt/turn start can. The same guard applies to native sessions outside tmux. Agents without a turn identifier retain session-level guards; this is not a claim of universal event ordering.

Codex's tmux fallback accepts the bound rollout's latest task_complete or turn_aborted only after the current active and waiting timestamps. A newer task_started, session mismatch, changed cwd, future timestamp or absent binding prevents reconciliation. The aborted path retains interrupted and does not stamp a successful finish. Native Codex rows also consult their own rollout; no protocol or UI shape changes are required.

## Doctor and configuration upgrades

Run `gtmux doctor`, then `gtmux doctor --fix` for the proposed repairs. Installed agents get checks for the actual command/token, matcher, disabled handlers, format and plugin template, rather than mere event names. Claude, Codex and Kimi keep their dedicated installers; the other hook-equipped entries are derived from the registry.

Repair replaces only gtmux entries, backs up changed files, preserves foreign hooks and Kimi's bytes outside the managed block, and verifies the resulting configuration. Unclear managed-block boundaries and invalid JSON are refused. Global hook disable settings remain the user's choice; doctor reports them instead of silently enabling them. Gemini's [hooksConfig toggle](https://geminicli.com/docs/reference/configuration/) is checked as well.

Configured does not prove loaded: restart the affected agent when convenient, review Codex hook trust in `/hooks`, and inspect hook traffic. Doctor does not restart live sessions or bypass trust. Project/system configuration and managed organization policies may override home-level hooks; the existing traffic check helps distinguish configured from actually emitting events.

## Verification scope

Regression coverage exercises tmux and native cancellation, late callbacks and newer turns, payload outcome classification, bound Codex rollout reconciliation, poller notification suppression, wrong/disabled bindings, foreign configuration preservation, Kiro V2→V3 migration, and plugin migration. The generated OpenCode JavaScript module is executed under Node with the documented SDK/shell contract, including child sessions and error→idle deduplication.

This is contract and regression validation, not a live end-to-end execution of all eight upstream applications. Older upstream versions may not emit newer events; unsupported interruption paths continue to rely on existing screen/transcript sensing. Re-audit these primary contracts when changing an integration, and keep this page, its Chinese pair, installers, doctor and OpenSpec aligned.
