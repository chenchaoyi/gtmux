# 工作台阅读与人类协作

当前问题独立于进展历史。HQ 使用 request-input，提供 matter、revision 和 user_input（id、kind、prompt、why、impact、可选 choices）。类型分别为选择、手动操作、补充信息；一个请求只说明一件具体事情。工程待办、普通进展、已兑现的许可不放进人类待办。clear-input 引用原问题 ID 并记录核实后的答复或新事实，只撤下这条请求，不把持续目标直接标完成；原问题和回执保留。

原生工作台选择选项时仅准备有归属的草稿，确认发送后沿原持久指令通道提交并关联 reply_to。重复提交收敛，过期问题拒绝写入；取消尚未尝试发送的答复会恢复问题。已保存不代表已送达或已执行。手机选项沿现有 HQ 输入框准备普通消息，由 HQ 收到后核对并撤下原问题；选中或草稿不授予权限。旧服务仍可读，未说明具体问题的旧记录归入“由 HQ 跟进”。兼容字段 needs_input 保留，新客户端使用 human_input 与 awaiting_hq。

浏览器 Trace 的分析与呈现由 App 纯 TypeScript 模块生成，调用分类和图标沿用已有一致性检查。长对话总览复用同一索引、源轮次和摘要，只覆盖已加载部分，最多绘制 120 个标记；键盘和指针仍能到达每轮。移动端点按预览保持打开，由显式操作跳转。刷新保持历史阅读位置，导航不向 agent 发输入，也不获取未共享内容。

终端留白放在 xterm 元素上，与 FitAddon 的计算契约一致。宿主尺寸观察覆盖输入区、最大化和窗口变化；交给终端自身换行重排，不重复清屏。关闭面板或切换模式时释放观察器，并拦住延迟适配回调。

精确 pane 跳转只核目标存在、选择对应窗口和 pane、激活所在终端，不再为一条可选提示先扫描整个舰队。终端驱动和原生标签身份定位继续沿用既有兼容路径。
