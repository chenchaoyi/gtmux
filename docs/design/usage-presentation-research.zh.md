## 展示决定

手机和 Mac 使用相同的信息顺序：

1. **额度与余额**：平台报告的额度百分比、重置窗口，以及准确的账户余额。各自保留单位和周期。
2. **输出 Token**：本机记录的总量、已有活动图表，再给紧凑的“按 Agent 统计”明细，共用今天／近 7 天列头。
3. **会话**：保留现有按异常和活动排序的会话明细。机器资源仍在各端原有位置。

“历史与数据来源”紧挨着它解释的额度，默认收起。里面保留旧额度条、读不到数据的原因、
账户余额能力限制、历史套餐原始标识和观测时间。同一 agent 同时有新旧窗口时分别保留；
旧记录使用中性灰。是否旧记录仍由核心的 stale 标记决定，旧服务没有标记时沿用原含义。

没有可读的当前额度或余额时，只显示简短的不可用说明。缺失的余额不能画成零。
本机输出数据与账户来源独立，只有输出记录的 agent 仍可参与输出统计。
金额保留原十进制字符串与币种，不合计不同币种。

观测时间仍可在折叠说明中查看；当前窗口的重置时间继续跟随额度条。主区域注明“平台报告”，
输出区域注明“已记录的对话、按当地日期”。输出 Token 不代表账单，也不能直接换算为
平台的额度百分比，更不意味着能够看到同一账户其他设备上的所有使用量。

## 范围和验证

安装记录、旧会话和保存的套餐名称不能证明当前仍有订阅。Claude Code 官方的
[`auth status`](https://code.claude.com/docs/en/cli-reference) 说明登录状态，不报告退订；
它也支持 [API 和云平台认证](https://code.claude.com/docs/en/authentication)。
即使已取消续订，[本期结束前仍可能保留付费权益](https://support.claude.com/en/articles/8325617-cancel-your-pro-or-max-subscription)。
本次因此默认收起过时额度，不把账户标成“已退订”、不删除对话，也不新增账户探测。
要确认当前付费权益，需要平台提供的新鲜账户证据。

只修改现有 React Native 与 SwiftUI 用量视图，并拆出小型展示/数据辅助模块。
不新增接口、provider、登录、凭据读取、费用估算、轮询或后台扫描。
当前告警与最紧额度选择沿用现有规则；只有一条正常额度时不重复画顶部摘要，告警和机器警告仍突出展示。金额精度、新旧窗口混合及展开/收起行为有针对性回归。
原生预览使用合成资料；如提供模拟器截图，使用复用的 Simulator 原生壳加载当前 JavaScript，
不是新签名发行包，也不是实体设备或 VoiceOver 验收。CI 和作者自测不算独立 review。

核心 `internal/usage/daily.go` 的旧字段 `week_out` 实际累计今天和前六个连接机器当地日期，
不是自然周，也不是平台的计费或重置周期。两端详情和用量入口都改为“近 7 天 / 7d”，
不更换协议字段、不改变统计值。图表的“按周”模式仍是自然周分桶。
