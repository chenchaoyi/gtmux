# HQ 维护输入窗口

HQ 工作时，自动提醒不再提前进入 Codex 的后续输入队列，而是在 gtmux 原持久队列保留、合并。新鲜观测到精确目标已加载且空闲后，才尝试一次普通启动；自动路径不调用 steer、不入未来队列、不恢复会话，不在未知或不支持时换通道重发。采样到提交之间仍可能被外部轮次抢先，普通 start 此时可能追加到那一轮。用户文字和截图入口保持原契约。

已排队、尚未发送的轮换先保留维护窗口，新自动批次不 claim。已经粘贴的自有提醒仍按原精确校验修复，避免把自己的草稿卡死；已发送的轮换允许现有后继交接。读取预约失败只延后自动提醒，不授权输入。快慢 tick 都先处理正常轮换，原身份、回合结束、草稿和双帧保护保留。

超时保留原 routine 失败审计，并通过既有独立用户桌面通知请求提示；旧请求不重复 reset。这不授权清除已有 Codex 队列或中断真实会话。已经被接受的旧提醒仍可能阻碍现用会话立即轮换，新源码不撤回存量；真实恢复和通知送达另做安装后验收。

轮换登记与自动批次 claim 共享输入准入锁，明确预约与投递的先后。原生唤醒提交只记录受理及回执中的轮次，不证明因果上新开一轮，也不表示已读或事件已消费，不推进 HQ 消费游标。忙时保留重要原事件、优先级及原有用户通知和 quiet/follow 策略；现有十分钟通道兜底不冒称即时阻塞告警。

协议限制：已安装 Codex 0.169 没有原子 idle-only turn/start 前置条件。自动原生唤醒新鲜核对精确已加载空闲目标后只尝试一次普通 start，不排 future queue、不调用 steer；外部轮次仍可在采样到提交间启动。受理/观测到轮次不代表本请求因果上新开一轮或已被消费。忙/未知输入留在本地。轮换失败保留原 routine audit，并独立请求一次用户通知；系统实际展示待运行验收。
