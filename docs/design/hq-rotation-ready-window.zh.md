# HQ 维护输入窗口

HQ 工作时，自动提醒不再提前进入 Codex 的后续输入队列，而是在 gtmux 原持久队列保留、合并。新鲜观测到精确目标已加载且空闲后，才尝试一次普通启动；自动路径不调用 steer、不入未来队列、不恢复会话，不在未知或不支持时换通道重发。采样到提交之间仍可能被外部轮次抢先，普通 start 此时可能追加到那一轮。用户文字和截图入口保持原契约。

已排队、尚未发送的轮换先保留维护窗口，新自动批次不 claim。已经粘贴的自有提醒仍按原精确校验修复，避免把自己的草稿卡死；已发送的轮换允许现有后继交接。读取预约失败只延后自动提醒，不授权输入。快慢 tick 都先处理正常轮换，原身份、回合结束、草稿和双帧保护保留。

超时保留原 routine 失败审计，并通过既有独立用户桌面通知请求提示；旧请求不重复 reset。这不授权清除已有 Codex 队列或中断真实会话。已经被接受的旧提醒仍可能阻碍现用会话立即轮换，新源码不撤回存量；真实恢复和通知送达另做安装后验收。

轮换登记与自动批次 claim 共享输入准入锁，明确预约与投递的先后。原生唤醒提交只记录受理及回执中的轮次，不证明因果上新开一轮，也不表示已读或事件已消费，不推进 HQ 消费游标。忙时保留重要原事件、优先级及原有用户通知和 quiet/follow 策略；现有十分钟通道兜底不冒称即时阻塞告警。

协议限制：已安装 Codex 0.169 没有原子 idle-only turn/start 前置条件。自动原生唤醒新鲜核对精确已加载空闲目标后只尝试一次普通 start，不排 future queue、不调用 steer；外部轮次仍可在采样到提交间启动。受理/观测到轮次不代表本请求因果上新开一轮或已被消费。忙/未知输入留在本地。轮换失败保留原 routine audit，并独立请求一次用户通知；系统实际展示待运行验收。

原生提醒在提交前持久保存批次意图，包括原始完整正文、投递 ID 和条目指纹。提交状态未定或不确定时发生中断，原批次保留供核对，不重新合批或自动重发；独立的新事件仍可继续。终态先持久保存，再收口本地条目。记录缺失、损坏或冲突都不能授权重试或删除替换条目。忙时返队不能覆盖同键的新生产者。旧版没有意图记录的原生孤立认领也按不确定保留。旧交互式投递继续原有回执和修复合同。

轮换失败使用独立的 attention 通知，不依赖等待提示快照；只提供跳转操作，正常遵守专注模式。通知开关、系统权限、过期抑制和普通已解决提示保护保持。系统通知中心受理不等于实际弹出或用户已读。

身份诊断区分实际观察到的另一段会话与暂时缺少证据。驱动、会话、前端或 active 身份无法核实时，尚未发送的请求保留原截止时间且不输入；持续 60 秒仍无法核实则通过同一警示渠道告警一次。只报告实际已知原因，其余明确为未知。原身份恢复也必须通过所有既有重置守卫，诊断不增加输入权限。

认领指纹包含设备与文件编号、正文 SHA 和实际观察到的 ctime 变更时间；有界读取期间的元数据变化也会被拒绝。恢复只接受可识别的已中断发布：已拒绝投递返队后的共享 inode 可由生产者正常更新；不确定批次的保留链接仍须与原正文和 inode 完全一致。这是协作写者锁下的证据核验，不是针对同用户恶意改路径的原子 compare-and-unlink。

提交前以有界私有硬链接保留每个原认领的 inode，跨进程中断仍保持存活；身份锚点不依赖 ctime 精度，ctime 继续作为额外的变更核验。锚点缺失或归属冲突不授权清理。已知终态只收口自己的引用，最后移除日志；不确定批次保留原输入及锚点。最多准入 1,600 个锚点、200 份意图记录。有效记录中的冲突仅保护原批次及其认领目标，独立新条目可继续；记录损坏仍阻止整个自动通道。

### 身份告警与请求到期

身份暂时无法确认满一分钟时，只提醒一次，保留同一个轮换请求。先持久记录该请求已尝试提醒，再发布 attention；发布成功不代表系统已显示或用户已读。原因变化、重读请求和证据暂缺均不延长原来的三十分钟期限。期限内恢复准确身份后，仍须通过既有输入框、身份、目标、完成边界及锁守卫。到期必须终态结束，不发送输入。此合同修正旧 HRW012 把六十秒当作失败期限的断言；HRW016 保留并迁移其有效保护。
