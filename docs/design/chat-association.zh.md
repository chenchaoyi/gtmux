# 会话关联恢复

[English](chat-association.md)

终端中的助手仍在运行，不代表对话索引一定可读。索引损坏导致页面空白，是关联异常，不能据此判断历史已丢失。Chat 和 Trace 共用窗格读取逻辑；CLI 按指定会话读取历史的路径独立。

主索引仍要求完整、有效的 JSON。主索引缺失或损坏时，可从独立保存的 Codex 实时连接凭据中恢复**只读历史关联**。异常查找最多读取 128 个条目；凭据损坏、连接不唯一、存在更新的冲突凭据或数量超限时拒绝恢复。恢复前核对数据目录、窗格位置、客户端与根进程及后端进程的启动身份、TTY。JSON 前缀、标题、相同目录、启动参数和旧检查点都不能证明当前会话身份。`LoadLive`、发送权限和 restore 的原有校验保持有效。

当前已认证的桥接进程可在正常心跳中补回自己的主索引。原有连接轮次检查和写入锁继续生效；必须持有与自身完全一致且仍有效的独立凭据，再次核对进程身份。已有有效关联或凭据发生变化时不能接管。单纯读取历史不会写索引，也不重启、恢复任何用户会话。

读取接口用 `conversation-unassociated`（409）表示关联不可用，用 `conversation-unavailable`（503）表示读取失败；确认关联但尚无消息时仍返回 `[]`。App 和浏览器保留已显示的内容，明确提示异常并提供“重试”。只读恢复成功时返回 `X-Gtmux-Conversation-State: recovered`，不增加发送权限。

主索引和独立凭据都不可用时，不自动猜测归属。历史仍可通过单独验证的会话身份打开；后续成功的已认证根会话绑定可建立新关联。不要截取损坏 JSON 的前半段，或删除 frontend 字段来伪造旧版关联。

验证使用隔离数据和合成进程，不代表当前运行版本、真实终端路由、手机显示或真实会话修复已验收。测试设计：CAS-001 至 CAS-005。
