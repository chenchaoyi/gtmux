# Web 浏览器镜像：工作台版（WEB.md）

> 浏览器镜像的权威设计补充。可视参照 [mockup/gtmux-web.dc.html](mockup/gtmux-web.dc.html)（§01 到 §04）。
> mockup 含有提案；下文区分这些提案与当前实现。
> 实现入口 `internal/server/web/`（`index.html` / `app.js` / `style.css`）。底层复用现有
> 契约（`/api/agents · /api/pane · /api/transcript · /api/diff · /api/icon`），浏览器轮询视图数据，按需获取图标。
> 获准的输入使用 `/api/send` 和 `/api/upload`；权限和选项使用 `/api/share` 和 `/api/options`。
> 其他 pane、外观和配对流程使用 `/api/panes`、`/api/theme` 和 `/api/enroll`。

## 定位

浏览器屏大、有真键鼠。网页镜像不能照搬手机的单栏布局，它是桌面工作台。左侧 agent 目录按状态和窗口分组，
把列表中的 pane 拖到画板自由排列、缩放，像 tmux 那样自己组合视图。只有获准的 pane 才能输入。

## 红线：布局只改本地，输入按权限开放

真 tmux 能 split/kill/spawn，镜像不假装。「编排窗口与 pane」指的是用户自己的观察布局，
**不改动真实 tmux 树**。服务器确认当前设备有权限后，网页才开放 pane 输入。

**共享页可以打字时，失败必须说话。** 发送被拒时应说明原因并保留草稿，也不能覆盖用户新写的草稿。
`makeComposer` 把普通 HTTP 错误正文显示在输入框下方。403、409 和网络失败路径只在输入框仍为空时放回刚提交的文字；
已有的新草稿保持原样（[#1391](https://github.com/chenchaoyi/gtmux/pull/1391)）。网络失败只能说明送达未确认，网页不能断言没有发出，也不能自动重发。

## 1. 顶栏

gtmux logo · 布局预设下拉（Frontend trio…）· 贴齐网格开关 · 自动显示等待中的 pane 开关 ·
连接指示（server 名 + 状态点，不用 “live”）· 外观（Aa：字体/字号，沿用现有 settings）。

## 2. 左侧目录（session/window/pane 树）

- 工作台读取 `/api/agents`，按 needs-you→errored→working→idle→running 分组，再按窗口分组。同窗口多 pane 会有分组标题；当前标题不能展开或收起。顶部有搜索过滤。
- 单独的「所有 pane」浏览器从窄屏雷达进入，读取 `/api/panes`，包含普通 shell。它不是工作台左栏。
- 「所有 pane」中，普通 pane 的名字与另外两块屏同源（`plainLabel` ↔ macapp `PaneLabels.plain` ↔ mobile
  `api/types.paneLabel`）：`title`（跳过整条路径或命令本身）→ `win_name`（除非 tmux 自动改成了命令名）→
  `project` → `cwd` 末段 → `command`。只印命令时一台机器上的 shell 全叫 `bash`，没错，但什么也没区分
  出来。**三份实现、一条链**：改一处必须改三处，偏好顺序在 DESIGN §16。如果包括 command 在内的字段都为空，手机端最后会回退到 pane ID。
- 把左栏一行拖到画板，或双击该行添加 tile。如果该 pane 已在画板上，就把它置前。独立聚焦视图由 tile 的 ⤢ 按钮打开。
- 可收起：头部 ⇤ 收入；收起后画板左缘留带 waiting 计数的小标签（⇥）可重开。
- 可调宽：右缘 col-resize 拖柄，记住宽度（localStorage）。窄于 900px 时，顶层页面改用单栏雷达，不显示工作台。

## 3. 自由画板

- 每块 tile = 一个 pane 的实时 xterm 镜像（复用现有 `app.js` 的 xterm 写入 + 滚动锁定）。
- tile：拖标题移动、拖右下角缩放、可叠放/平铺；可选贴齐网格对齐。
- tile 头部：avatar + 角标状态徽章 · 名称 · `终端 / 对话 / diff` 切换 · ⤢ 全屏 · × 关闭。
- waiting tile 红边 + 轻脉冲。
- 多 pane = 多个并发 `/api/pane?id` 挂载；`diff` 用 `/api/diff?id`；`对话` 用 `/api/transcript?id`。
- tile 使用绝对定位；缩放某块不会让其他块回流。不拖动而点击标题栏中按钮以外的任意位置，会把该 tile 最大化到画板内；`f` 和 `1–9` 也能最大化。仅工作台可用的命令面板会添加或找到 tile，闪动提示，再把它最大化到画板内。用「还原」或 Esc 返回。这与 ⤢ 打开的独立聚焦视图不同。

## 4. 全屏聚焦（单 pane 细读，mockup §02）

tile 的 ⤢ 或窄屏雷达行，都能打开单 pane 聚焦视图。它提供「终端 / 对话」、上/下一个 pane，
以及终端字号、外观、复制选区或可见屏、跳到最新输出等控件。diff 留在工作台 tile 模式；聚焦视图没有 diff 标签或换行开关。
Esc 返回此前的顶层视图。

**窄于 800px（手机）。** 一行放不下整条工具条，顶栏会换行：第一行是返回、标题和服务器（标题先截断），身份、可输入两个标签和各个控件排在下面，宽度不够就再换一行。布局目标是适应视口；外观面板在顶栏下方打开。

**Codex 吸顶提示。** Codex 把屏幕上这一轮的提示固定在第 0 行，按 pane 宽度截断并加「…」。单 pane 终端视图里，对话记录中的完整提示显示在终端上方的提示条里（默认两行，点一下展开，有「复制」按钮），截断的那一行不再进终端。规则和手机一样（见 MOBILE.md）：`app.js` 里有一份 JavaScript 实现，跑同一份用例文件（`mobileapp/src/ui/codexPinnedCases.json`），用同一张按 tmux 实测的字宽表，以检查这些用例和字宽表的一致性。这一行在屏幕上却对不上时，每 4 秒最多拉一次对话记录。工作台的 tile 里不做：tile 放不下第二条栏，那一行原样显示。

## 5. 对话模式 · 宽屏版（mockup §03）

与移动端 `ChatView` 同源（`/api/transcript`：prompt → 中间步骤折叠 → agent 回复），为宽屏重排：

- 左侧轮次目录：列出每个 turn，`j`/`k` 跳转、当前轮高亮（大屏独有的全局导航）。
- 居中对话列（含内边距最大 820px）：用户气泡靠右 + 人类头像；agent 气泡靠左 + 官方图标；气泡悬停浮出「复制 / 引用」（桌面鼠标特性）。
- 等待卡：`/api/options` 提供解析出的编号和标签。获准输入的读者点击选项，通过 `/api/send` 发送编号，不带 Enter；只读读者能看见选项，但没有发送处理。只有解析出的选项才生成按钮；空结果或选项请求失败会清掉选项，绝不凭空生成 `1/2/3`。可输入的 chat 提示去终端回答，只读的提示用手机/Mac 回答。等待也可能是开放式问题，不一定是审批。
- 中间步骤可展开/收起。自由输入在**终端**，不在对话视图：多行输入框用 Enter 发送、Shift/Option+Enter 换行，另有图片上传和控制键栏。对话背景为深色。「复制 / 引用」都复制到剪贴板，引用不会直接提交。

## 6. 你的头像 · agent 时代的人类（mockup §03 附）

当前浏览器用固定的青色渐变圆底人形电池 SVG 表示没有发送者归属的用户提示。带发送者归属的轮次改用 HQ 字标，
或发出消息的 agent 头像（`senderAvatarEl`）。颜色不识别个人身份。

mockup 中其余款式（飞升 / 指挥家 / 拍板人 / 队长 / 休息中 / 橡皮图章 / 遛狗反转 / 仓鼠轮）、上传照片、emoji 和首字母
均是**提案，不是已实现的浏览器设置**，也不能据此说三块屏都有头像选择器。

## 7. 已交付的布局能力

- 命名预设将 pane ID、位置、尺寸、模式、左栏状态和网格偏好存入 localStorage，由顶栏保存/应用/删除。当前画板也会保存；恢复时只加入当前 agent 响应中仍能找到的 pane。可用的已存布局取决于浏览器存储和站点 origin。
- 自动显示等待中的 pane（可选）：每两秒的 agent 轮询检测进入 waiting 的变化，为尚未在画板上的 pane 加 tile 并闪动。跳过首轮，已有 tile 不重复加入。这是轮询行为，不是 SSE alert 处理器。
- 画板内最大化和独立的单 pane 聚焦视图都已实现；入口和模式区别见 §§3–4。

## 8. 键盘（桌面优先）

工作台中、焦点不在输入控件时：`⌘K` / `Ctrl+K` 打开 pane 命令面板；`1–9` 最大化第 N 块；`f` 切换最前面 tile 的画板内最大化；
`Esc` 还原；`g` 切换贴齐网格；`[ ]` 切保存的预设；`/` 聚焦目录搜索。聚焦对话中 `j/k` 切轮次、`c` 收起步骤；
聚焦终端中 `j/k` 切 pane。这些是网页快捷键，不是原始终端按键直通。

## 9. 状态 / 落地

- 雷达采用共享的色/形/字形词汇。连接点随轮询失败改变；tile 请求失败时当前实现保留旧内容。虽然有未使用的 CSS 类，但并未实现逐 tile 的离线灰色遮罩。
- `web/app.js` 已有画板布局引擎（绝对定位、拖拽/缩放、localStorage）、预设、等待 pane 自动浮出和聚焦视图。窄于 900px 时顶层改成 radar→pane。
- 这些布局能力已完成原来的分阶段交付；不包含 §6 提议的头像选择器和 §10 提议的 HQ 指挥台。

## 10. 浏览器语言与 HQ 指挥台提案 · §07 mockup

### 语言：跟浏览器走

这一页跟浏览器的语言走，因为浏览器镜像是唯一一块你交到别人手里的屏。分享链接的收件人是访客，
最不可能读得懂 host 的语言，而这一页曾经漂成了「中文界面 + 少数几处双语」（gate 屏和连接状态提示是双语的，
其余不是），英文读者打开访客链接会看到一页他操作不了的东西（2026-09-07 修）。

它先读 `navigator.languages` 的第一项，再回退到 `navigator.language`，和手机端跟随设备语言一个道理；这里没有 `GTMUX_LANG` 可读，
打开它的人可能根本没装 gtmux。`index.html` 中的中文在 boot 时由 `CHROME` 及 `labelChrome` 的其他赋值重新贴标签。
动态文案使用 `T(en, zh)` 或语言分支，不是每个可见字符串都在同一张表里。

**gate 屏例外，它继续同时显示两种语言**：那是你截图发给能修的人的那块屏。

访问页同时服务 Mac 主人和分享链接的访客：输入框说明可用配对码或分享码，失败提示只说明核对或换码，不假定读者有分享者。空对话页直接提示切换到终端，不把 agent 的会话日志说成 hook 记录。只读状态直接说明该 pane 不允许输入。

`internal/server/webui_test.go` 检查一份明确列出的控件 ID，并扫描附近没有语言切换的中文字符串。这是源码检查，不能证明每个控件都已翻译或翻译内容准确。

标签/按钮的英文大小写按 DESIGN §11 / MOBILE §6 的三档规则（名字与动作句首大写、状态词全小写、
键名全大写小字），这一页落地时直接照抄，别再各写各的，手机端就是这么漂移到「大小写很随意」的。

**提案，不是已交付的 Web 路由：** 左舰队态势（`/api/digest`）、中与 HQ 对话、右派活台账（`/api/tasks`，spawn/reap）三栏，
仅 owner 可用，窄屏竖排。当前 Web 页面没有 HQ 指挥台，也没有调用这些 API；HQ 仍在现有 pane/雷达和发送者归属视图中表示。
不能仅因后端已有对应接口，就把专属指挥台、置顶和断点布局说成已交付。

## 11. 输入能力 + 权限透出 · §08 mockup

网页经 `POST /api/send` 发送，不使用 CLI 的原始 `/api/attach` WebSocket。`/api/share` 返回后，聚焦 pane 和 tile 都显示输入权限。
获准的**终端**视图有输入框；只读视图用说明代替输入区。获准的读者也可点击聚焦对话中解析出的选项。

owner 可输入其 owner 凭证控制的 pane；guest 需同时满足该分享链接的输入范围（输入⊆可见）、host 的「允许协作者输入」开关，且授权仍有效（`GrantsStale` 为 false）。
顶栏区分 owner 和 guest。服务器在请求时检查权限，撤销后该凭证的新请求会被拒绝。
这条 HTTP 说明不代表独立 CLI attach 流的范围或关闭时序。
