# HQ maintenance input window

Automatic wake notifications must not fill the Codex future-input queue while HQ is working. Keep/coalesce them in the existing durable gtmux queue; freshly observed loaded-idle metadata is required before one ordinary start attempt. The automatic path never calls steer, queue or resume and never changes permissions or falls back after unknown/unsupported responses. An external turn can win the sampling-to-submit race; the ordinary start may then append to that turn. Explicit human and screenshot ingress retain their existing contracts.

A queued, unsent rotation reserves new automatic batches before claim. Existing exact stranded-wake repair remains allowed so maintenance cannot trap a previously pasted draft. Sent rotations release this reservation for the existing verified successor bootstrap. Read-only reservation failures hold automatic input rather than authorize it. Rotation runs before wake drain on both normal cadences; all current identity, completed-turn, draft and two-frame guards stay in force.

Timeout keeps the original routine failure audit and requests an independent owner desktop notification, once per failed request. No reset is repeated. This is not permission to clear existing Codex queue entries or interrupt a real session. Already accepted old inputs can still delay a currently deployed rotation; new source does not retroactively withdraw them. Runtime/client recovery and notification delivery require actual installed acceptance.

Rotation registration shares the automatic-input admission lease, so reservation and claim have a defined order. A native wake submission is recorded as accepted with an acknowledged turn ID, not a causally new start, read or consumed event; it does not advance HQ consumption watermarks. Busy retention preserves important source events and existing owner notifications, priority and quiet/follow policy. The 10-minute channel watchdog is not an immediate blocked-task alert guarantee.

Protocol limit: installed Codex 0.169 has no atomic idle-only turn/start precondition. Automatic native wake samples exact loaded-idle metadata and attempts one ordinary start, never calls queue or steer; an external turn can start between sampling and submission. Accepted/observed turn is not proof that this request caused a new turn or was consumed. Busy/unknown inputs stay local. Rotation failures retain the original routine audit and enqueue one independent owner notification; OS presentation remains runtime acceptance.

Native wake crash recovery uses a durable pre-submission batch intent, retaining the exact original payload, delivery ID and entry fingerprints. An interrupted prepared/uncertain batch is preserved for reconciliation and never regrouped or automatically replayed; independent new events may proceed. A terminal result is persisted before local cleanup. Missing, malformed or conflicting evidence never grants permission to retry or delete replacement work. Refused claims return without replacing a newer keyed producer. Older untracked native orphan claims are retained as uncertain. Legacy interactive delivery keeps its existing receipt/repair contract.

Rotation failure is an explicit attention notification, independent of waiting-prompt snapshots, with Jump-only actions and Focus-respecting active delivery. Existing notification settings, permission, stale suppression and ordinary resolved-prompt protection remain. System-center submission is not proof of actual OS presentation.

Identity diagnostics distinguish an observed different conversation from unavailable evidence. An unsent request holds without input on unknown driver/session/frontend/active identity, retaining its original deadline. Persistent unavailability is reported once after 60 seconds, with a value-free known cause or explicit unknown, through the same attention channel. Recovery of the exact original identity does not bypass any existing reset guard. Diagnostic status adds no input authority.

Claim fingerprints include inode/device, payload SHA and observed ctime generation. Metadata changes during the bounded read are rejected. The only legitimate recovery exception is a recognized interrupted publication: the refused queue may own an updated shared inode; an uncertain parked link must still match the original payload and inode. This is evidence checked under cooperating writers, not an atomic filesystem compare-and-unlink against hostile same-user path mutation.
