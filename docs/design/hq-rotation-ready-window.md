# HQ maintenance input window

Automatic wake notifications must not fill the Codex future-input queue while HQ is working. Keep/coalesce them in the existing durable gtmux queue; only an explicitly loaded idle thread may receive one normal start. The automatic path never steers, queues, resumes, changes permissions or falls back after unknown/unsupported responses. Explicit human and screenshot ingress retain their existing contracts.

A queued, unsent rotation reserves new automatic batches before claim. Existing exact stranded-wake repair remains allowed so maintenance cannot trap a previously pasted draft. Sent rotations release this reservation for the existing verified successor bootstrap. Read-only reservation failures hold automatic input rather than authorize it. Rotation runs before wake drain on both normal cadences; all current identity, completed-turn, draft and two-frame guards stay in force.

Timeout is an important audit and an existing desktop-notification request, once per failed request. No reset is repeated. This is not permission to clear existing Codex queue entries or interrupt a real session. Already accepted old inputs can still delay a currently deployed rotation; new source does not retroactively withdraw them. Runtime/client recovery and notification delivery require actual installed acceptance.
