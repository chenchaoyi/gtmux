# 服务器访问历史

## 用途与入口
所有者可以查看哪些配对设备或浏览器访问过本服务器、何时访问、请求了什么操作，以及 HTTP 结果。这里记录请求，不保存对话，也不代表 agent 的任务完成情况。

- 终端：`gtmux logs --access`；`--json` 返回分页对象，`--before <cursor>` 读取更早记录，支持 `--limit 1..200`、`--since 3d` 和 `--actor <完整设备 ID>`。
- 菜单栏：偏好设置 → 配对设备 → 访问历史。本机窗口读取 CLI 的统一结果。
- 手机与 iPad：设置 → 管理服务器 → 访问历史。共用页面，支持刷新、载入更早记录，并明确提示服务器版本不支持、权限不足或分页过期。访客不能查看此页面，也不能读取对应 API。
- Web：浏览器请求纳入记录，提供所有者 API。本次不新增浏览器内的历史查看页。

## 记录范围与隐私
诊断库中的 `serve/access.request` 是信息级操作记录，包含操作 ID、时间、已验证的凭据范围、可用时的完整设备 ID、当时的设备名称及平台、可信来源 IP、限定词表中的操作、可选 `%pane`、方法、状态、结果及耗时。名称和平台仅供辨认，不参与身份验证。所有者凭据由多个客户端共用，无法确定实际设备或使用者。代理地址仍按现有服务器信任规则处理。

覆盖已认证的会话、终端、对话、HQ、知识库、用量及设置读取，以及输入、切换窗格、新建会话、上传、共享、配对设备与通知管理、线路及跟进设置。未分类的已认证 API 请求显示为“服务器请求”。兑换成功记录最终验证的设备或共享链接，不记录兑换码。图标、主题资源、公开静态页面及健康探测不纳入访问记录。兑换失败原因仍在原有配对诊断中。未知或缺失 bearer 凭据沿用全局每分钟一条的采样，后续计数写入诊断汇总；不能将其当作逐次入侵记录。

成功的 GET/HEAD 按完整身份、操作及窗格，每五分钟记录一次；这是采样，不是请求次数。读取失败和普通 HTTP 写入请求逐次记录。SSE 与远程终端在实际建立和关闭时分别记录，建立失败也保留。服务器被强制结束时无法记录关闭回执；attach 流中的每次按键不单独记录。

不新增授权头、token、配对或共享码、查询参数、请求或响应正文、命令文本、图片及对话内容。继续使用统一脱敏。HTTP 成功仅表示请求被接受，不代表 agent 已完成任务，上传记录也不包含文件内容。

## 存储、查询与失败处理
复用 `~/.local/share/gtmux/logs/`，沿用 `logs.retainDays` 和 `logs.maxMB`（默认 30 天 / 100 MiB）；诊断与访问记录共享容量上限。从升级后开始记录，不补造历史，也不自动上传。所有者可以主动复制或导出私有记录；诊断包也会包含这些记录，分享前应检查内容。

按时间倒序，每页默认 100 条、最多 200 条，每次最多扫描 4 MiB。未找到匹配记录的页仍可能提供更早的游标。游标只允许经过校验的日志文件名及偏移，不能选择任意路径；记录被清理或截短后返回 HTTP 410，读取失败返回 503，不伪装为空历史。刷新从最新记录开始。翻页出错保留已载入内容，切换服务器后忽略旧响应。手机和 iPad 使用虚拟列表及适合阅读的宽度，完整设备 ID 默认收起；本机窗口使用相同分页模型。

写入失败沿用限频 stderr 提示和 doctor 写盘探测，不因审计失败阻止终端输入或会话管理。这些日志用于排障和操作核查，不是防篡改账本。

## 本机权限
诊断追加写入只打开本人所有的普通文件，不跟随末级目录或文件的符号链接，通过目录描述符打开文件，并收紧现有组及其他用户权限。gtmux 数据、配置根目录及日志目录仅限本人访问，文件权限不超过 0600；其他所有者或非普通文件会被拒绝。历史只读查询不修改权限，也不读取不安全的末级链接。

doctor 检查整个 gtmux 数据及配置目录的 POSIX 权限、所有权、不可读路径及无法核实的符号链接。`doctor --fix` 只收紧本人路径，不跟随链接；无法核实的情况需要单独检查。POSIX 检查不验证 ACL，也不能阻止文件所有者或 root 修改，不能防御所有特权文件系统操作。

## 验证
隔离测试覆盖身份与伪造请求头、访客及未知凭据拒绝、读取采样与逐次写入/错误、连接生命周期和建立失败、敏感内容排除、分页预算及游标、保留期筛选、符号链接拒绝和权限收紧。组件测试覆盖旧服务器、重试、去重、切换服务器及设备标识展开。CI 编译原生与 iOS 客户端。真机布局、键盘和 VoiceOver 行为仍需实际验收，不能用单元测试代替。
