# 存储与 HQ 恢复

自动恢复点与全量导出范围不同；两者都不等于已有异地备份。本轮不会迁移或删除现有档案。

## 自动恢复点

`gtmux config snapshots` 仅显示备份设置。可用 `on|off`、`--keep`、`--max-mb`、`--interval-minutes` 修改这一项，不输出完整配置。默认开启，保留三个内容发生变化的恢复点，托管总预算64 MiB，两次尝试至少间隔十五分钟。这是三个恢复点，不承诺覆盖三天；关闭自动恢复也不删除现有文件。

JSON 配置为 `hqSnapshots`：`enabled`、`keep`（1–30）、`maxMB`（1–2048）、`intervalMinutes`（0–1440），以及可选的 `include` 精确相对文件/目录路径。配置损坏时拒绝生成和裁剪；缺项使用共用默认值。

核心范围保护指令与个性化规则、全部知识库文件、事项记录及普通笔记，未知结构化笔记也保留。符号链接不跟随，workspace 隐藏运行文件继续排除。notes 中的图片、视频、PDF/归档包和原始日志属于过程附件；命名的全量 relay JSON 列表，以及 `*-relays-final.json`、`*-relays-verified.json`、`*-relays-closeout.json`、`*-relays-closure.json` 等明确的生成观测阶段转储，属于过程材料；不匹配该规则的 summary/analysis 笔记继续保留。notes/reports 中保留文字结论及 SUMMARY/FINAL/INDEX/OWNER/RETAINED/retention JSON，其余为过程报告。若其中某文件或子树有独有价值，可用 `include` 明确纳入。声明过程范围之外的未知笔记不会仅凭体积被丢弃；独有文件超限时，整个新备份失败。

新点存于 `hq-snapshots/automatic-v1`，与父目录的旧包分开。包仍为标准 tar/gzip，旁边的私有版本回执登记内容摘要、包SHA、大小和验收时间。内容及所有者权限摘要不依赖修改时间或日期，跨日内容不变不会再存一份；同日的不同状态可以保留为不同恢复点。

发布前使用实际导入读取器核验全部 gzip 尾部、归档限制和事项结构。新包及回执完成持久发布并再次核验后，才裁剪本版本登记、验包通过且未变化的点。份数和压缩字节预算在成功发布后生效，并预留回执/状态空间；生成中的单包也受配置预算与导入上限中较小值约束。未知、损坏或未提交文件保留并计入预算，必要时挡住新包。失败保留旧点，并在档案/诊断信息中显示。并发尝试沿用跨进程存储锁。

**现有十四份旧包不会被接管或裁剪。** 新默认、关闭备份、生成失败，甚至已有一份新的有效核心恢复点，都不能证明旧全量历史状态可删。旧包恢复能力另行核验。

## 显式全量导出

`hq --export` 与 owner HTTP 导出继续包含完整档案，包括过程报告和附件；不会静默变成核心子集。明文、口令加密和流式下载共用现有导入限制：压缩输入与解压 tar 各128 MiB、单文件32 MiB、10,000 条目。读取器按已校验的单文件长度分配缓冲，减少大量小记录的额外内存分配。压缩、展开和单文件字节上限不变。超过 5,000 条目的恢复点需使用 1.0.168 或更新版本；旧读取器明确拒绝，不会部分导入。超限的全量导出在替换目标或发送HTTP正文前失败，不为了过程档案盲目提高导入内存预算。

导出先在私有临时文件中完成、完整验包，再原子发布；目标须在HQ家目录之外。超过上限的全量档案需另行管理的文件系统备份，或后续有界流式导入设计；本轮不声称旧超限包已可导入。核心恢复时，原家目录整体移到旁边，未纳入的过程附件也在原目录副本中保留。恢复的历史待发指令继续标为不确定，不重放为新授权。

## 交付材料

默认的 gtmux 配置和数据目录（`~/.config/gtmux/`、`~/.local/share/gtmux/`）只存
gtmux 自身管理的配置、运行状态和归档，不是通用项目工作区或交付库，即使正在开发
gtmux 项目也不例外。项目代码、脚本、文档和交付归项目自有目录；构建、fixture、
下载和原始证据归任务临时目录。工作树外确需保留的交付，使用项目自有归档并登记下述
保留规则，不在 gtmux 应用数据中另建目录。HQ notes 只留简短协作摘要和证据引用，
不再复制项目材料；`knowledge/tools/` 只放可复用的 HQ 知识工具。

这条边界内置于各 agent 的全局托管指令块和 HQ 第60版章程。知识同步保留用户正文及
手改块保护；正常 HQ 升级保留 LOCAL.md 与既有档案。新规则不自动迁移或删除旧材料。
存储统计继续展示历史 reports、reviews 和发布目录，但目录已存在不等于允许继续放入
一般项目材料。面向用户的报告链接使用项目交付地址；受保护的配置目录不能远程预览。

编译中间产物、临时下载和一次性解包验包目录留在任务/构建存储，随任务收尾。可复现正式产物以发布渠道为主。跨任务保留属于例外：使用明确的交付归档位置，与应用运行数据分开，并用 `retention.json` 登记用途、源码/构建/渠道、字节预算、最短保留期、复核日期与责任人。复核到期不等于可删除。格式见 `delivery-retention.schema.json`，可用 `scripts/check_delivery_retention.py` 检查。

仅保留独有签名/恢复材料、必要符号和简明最终验收证据；不默认同时保留多份运输包和解包副本。清单不放凭据。当前和前一交付、有效Store/在飞分发以及独有恢复证据，在实际替代与恢复链核实前继续保护。旧材料须有精确退役计划；年龄、相似大小、即将过期的CI产物或新增副本都不能单独证明可删。

放在工作树之外也不是永久保留。迁移到同盘另一个目录不会释放空间，本轮不迁移已有档案。已有正式交付、Store及重启证据沿用原保护规则。

## 存储展示

共用诊断投影分别统计运行数据、自动备份（hq-snapshots）、发布恢复（releases、appstore）、验收档案（reports、reviews、verification）和待分类数据。未知顶层目录不再统称运行状态。总量旁给出来源目录和备份配置入口；归档很大不等于运行数据故障。

`hq --records --json` 增加 `automatic_backup`：生效规则、新旧包容量/数量、发布验收时间和最近失败。旧包数不是已验恢复点数。菜单栏读取这份投影，遇旧core保守显示未核验，不自行解释存储文件。文件逻辑长度、目录分配量与并发卷可用量分别记账；本轮源码机制迭代不宣称释放若干GB。

使用隔离合成HOME验证范围、实际恢复、旧包保留、预算/关闭、跨日内容去重、并发、损坏/超限、目标保留和分类。不向真实HQ导入，不读取私人桌面对话。
