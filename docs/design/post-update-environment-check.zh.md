# 更新后的运行环境检查

## 1. 流程

CLI 更新成功后，由新安装的程序执行 `doctor --no-prompt --progress`，限时 90 秒。
安装与检查分别报告：检查失败或超时会提示重试 `gtmux doctor`，不改变安装退出码。
`GTMUX_ACTOR=menubar` 时跳过旧进程中的检查。

新版 Mac App 启动后运行 `doctor --json --no-prompt`，每个 App 版本自动检查一次。
UserDefaults 保存已尝试的版本及最近一次有效报告。检查失败会显示出来，不反复自动重试；
用户随时可以手动重试。报告必须为 schema 1、数量与各行一致、CLI 版本与当前 App 一致，
退出码也须与阻塞项一致。无效结果不会覆盖旧报告。

## 2. 呈现与修复

菜单底部显示检查进度、未完成或待处理项。正常结果可从齿轮菜单、偏好设置 → 诊断查看，
不常驻提示。结果窗口按 doctor 原有分组呈现状态、说明和可访问性标签。
新一轮检查失败时，明确标明下方保留的是旧报告。

「查看修复方案…」调用 `doctor --fix --terminal`，在交互终端里以同一个程序执行
`doctor --fix`，不附加 `--yes`。各项修复沿用已有的说明与确认。
打开终端不等于修复成功；用户完成后重新检查。部分检查项只能手动处理。
本功能不会自动安装软件、修改配置或重启服务。

## 3. 进程边界

Mac 检查使用私有临时文件收集输出，避免子进程持有管道导致一直等待。
每个输出流最多读取 1 MiB；超时终止检查进程，两秒仍未退出则强制结束；临时文件随后清理。
Go 路径使用 CommandContext 与 WaitDelay。

没有新增 HTTP 接口或手机、网页修复入口。报告仅存于 Mac。
同版本重装不会再次自动检查，可手动点「重新检查」。首次使用此功能也会检查一次。
手动检查保持只读。

## 4. 验证

CLI 与 Swift 隔离测试覆盖报告与退出码、拒绝变更参数组合、新程序路径与超时、
报告持久化、重试、版本不匹配、打开修复终端失败及标准输出/错误输出。
测试不修复真实环境，也不替换正在运行的 App。实机视觉与 VoiceOver 验收另行记录。
