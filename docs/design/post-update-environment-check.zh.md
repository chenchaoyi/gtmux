# 更新后的运行环境检查

## 1. 流程

CLI 更新成功后，由新安装的程序执行 `doctor --no-prompt --progress`，限时 90 秒。
安装与检查分别报告：检查失败或超时会提示重试 `gtmux doctor`，不改变安装退出码。
`GTMUX_ACTOR=menubar` 时跳过旧进程中的检查。

新版 Mac App 启动后运行 `doctor --json --no-prompt`，每个 App 版本自动检查一次。
UserDefaults 保存已尝试的版本及最近一次有效报告。检查失败会显示出来，不反复自动重试；
用户随时可以手动重试。报告必须为 schema 1、数量与各行一致、CLI 版本与当前 App 一致，
退出码也须与阻塞项一致。无效结果不会覆盖旧报告。

## 2. 呈现与修复

菜单底部显示检查进度、未完成或待处理项。正常结果可从齿轮菜单、偏好设置 → 诊断查看，
不常驻提示。结果窗口按 doctor 原有分组呈现状态、说明和可访问性标签。
新一轮检查失败时，明确标明下方保留的是旧报告。

「查看修复方案…」调用 `doctor --fix --terminal`，在交互终端里以同一个程序执行
`doctor --fix`，不附加 `--yes`。各项修复沿用已有的说明与确认。
打开终端不等于修复成功；用户完成后重新检查。部分检查项只能手动处理。
本功能不会自动安装软件、修改配置或重启服务。

## 3. 进程边界

Mac 检查使用私有临时文件收集输出，避免子进程持有管道导致一直等待。
每个输出流最多读取 1 MiB；超时终止检查进程，两秒仍未退出则强制结束；临时文件随后清理。
Go 路径使用 CommandContext 与 WaitDelay。

没有新增 HTTP 接口或手机、网页修复入口。报告仅存于 Mac。
同版本重装不会再次自动检查，可手动点「重新检查」。首次使用此功能也会检查一次。
手动检查保持只读。

## 4. 验证

CLI 与 Swift 隔离测试覆盖报告与退出码、拒绝变更参数组合、新程序路径与超时、
报告持久化、重试、版本不匹配、打开修复终端失败及标准输出/错误输出。
测试不修复真实环境，也不替换正在运行的 App。实机视觉与 VoiceOver 验收另行记录。

## 5. 报告可读性

每行使用包含分组身份的唯一标识，避免其他分组的检查项被错误复用；条件检查项
插入时，展开状态也不会转移到另一项。窗口按明确分组滚动展示，阅读宽度最多 760 pt。

已知检查项在 JSON 中使用易懂的名称，可选字段 `description` 说明实际检查内容。
状态、结果和 `note` 仍来自原检查。未知项保留原名称和备注，旧报告没有说明字段时
仍可阅读。展示名称不作为固定的机器标识。

窗口名称由系统标题栏呈现，结果摘要和检查名称使用 `Theme.Font.session`（13 pt），
说明、结果及操作使用现有的 12 pt 正文字号。检查目的直接展示，完整结果和技术备注
从检查摘要旁的系统展开箭头进入，不再额外占用一行「技术详情」。行上下内边距为
6 pt，分组间距为 16 pt。过长的结果预览最多两行，悬停或展开详情可查看全文。文本沿用系统
语义颜色，建议项图标使用统一的橙色。摘要明确区分需要处理、建议处理和正常项；
检查时间按应用所选语言显示日期与时间。

## 6. 完成状态、分类和事项汇总

完成状态表示检查流程是否结束。有建议项的报告仍然属于检查已完成；超时或无效
报告才是检查失败，此时保留并明确标注上次报告。摘要显示正常、建议处理、影响功能、
信息四类数量，只有建议项和影响功能项进入需关注清单。信息项可包含未启用或
未核实状态，不作为正常通过的检查统计。

CLI 报告末尾列出全部需关注事项，影响功能项优先，保留分组、结果和处理说明。
修复后沿用同一汇总，区分建议项与修复执行错误。重新检查和展示汇总都不会自动
修复，退出码判定规则沿用原有逻辑。

Mac 报告末尾展示紧凑汇总，固定的顶部和底部入口可直接跳转。选择事项会定位、
高亮原检查项并展开完整详情；再次选择已手动折叠的同一项也会重新展开。
汇总行与原检查行使用不同身份，避免导航目标冲突。检查项数量有限，分组内容
一次布局，确保点击时可定位到原行。顶部信息按钮解释四类结果。重新检查失败时，
仍明确指出可见报告及其事项来自上次成功检查。

Mac 检查项只展示一次当前结果。展开后保留补充说明；长结果展开为全文时，收起右侧摘要。同标题、检查目的或结果完全相同的文字不再重复展示。旧报告的独有说明仍会显示。
