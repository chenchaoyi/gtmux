# Clio 与 HQ 主题整理

研究记录，2026-10-20。以下是接入建议，主题自动发现尚未实现。

## 可借鉴的方法

Anthropic 的 [Clio 介绍](https://www.anthropic.com/news/clio) 将对话属性提取、相似内容归类、命名与分层串成流程；[论文 §2.2 与附录 B](https://arxiv.org/html/2412.13678v1) 说明了向量表示和 k-means 聚类。它们适合从杂乱历史中寻找主题线索。

## 放到 gtmux 怎么用

一段对话可以有多个目标，一个目标也可以跨多个 Agent 和会话。候选整理单位应是围绕一个目标的对话片段，保留原始消息 ID、时段、预期结果、涉及产物、约束和明确引用。先认已有事项 ID、原任务引用、PR／issue 与已记录的会话关联，再用语义相似度补充。

没有明确关联的片段，可以提出少量“归入已有事项／新建事项”的候选，附证据和理由；判断不清就保持未归属。“gtmux 界面”这类宽主题可用于导航，不足以把不同任务的执行历史合并。用户或 HQ 的纠正应沿用稳定 ID，保留明确的合并、拆分记录。

增量处理新内容，缓存未变的片段，并使用单独的读取位置，不能借用或推进 HQ 的事件消费位置。第一步可由现有 HQ 工作流处理限量片段，无需先部署向量数据库或常驻分类服务。若以后引入外部模型处理，先明确数据范围，只提供必要原文。

## 边界和验证

论文 §2.3 的聚合隐私保护包含规模门槛与审计，也没有宣称形式化差分隐私保证。个人任务往往只有一次对话，却要准确保留文件、PR 等产物；照搬“隐藏少数主题”会漏掉工作。应在本地保留出处、控制模型输入，不能把原系统的聚合保护直接当成本产品的保证。

验证时要把主题分类与任务归属分开：同项目不同目标不能误合；同目标跨会话仍要能关联；覆盖纠正、中文／英文目标切换和证据不足的情况。用模拟或脱敏样例检查误合、漏关联、引用准确度和标签稳定性。聚类本身不授权发送、关闭、归档或标记完成，当前明确的事项台账仍是依据。

## 本轮范围

原生总览只读取明确事项记录中的有限节选，没有启用上述自动整理、重组对话或修改 HQ 说明书。汇报、状态及来源边界见 [HQ 工作台](hq-workspace.zh.md)。
