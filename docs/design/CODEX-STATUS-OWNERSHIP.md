# Codex status follows the current thread

A pane can retain a named active marker from a previous/different session. Recent window activity alone must not revive that marker as current work. The shared radar accepts a display correction only with a verified live current home/session/cwd, a different named marker, its own completed or aborted rollout and a ready terminal without work/queue/approval evidence. A legacy saved resume record alone is not an exclusive frontend witness, so it cannot enable this correction. Unknown or legacy unnamed markers remain conservative; genuine starts and approvals still win.

This correction neither rebinds the pane nor removes a marker. It uses the current thread end time for display without writing the idle cache, preserves an actual interruption outcome and does not mark the pane as a new/latest confirmed completion. Waiting resolution reuses the pre-hook frame/CPU observation rather than treating a hook-derived working status as new activity. All consumers receive the same radar status.

Tests isolate HOME, state, logs, process and terminal boundaries; no real input/marker cleanup, private conversation body or binding token is used. The origin of a historical foreign marker is not inferred from its presence. No release/install or permissions change is included.
