# HQ 选项反馈与独立读取

选择选项只在当前事项准备草稿，显示勾选及已填入提示，并通过既有原生多行输入框请求焦点。它不会发送答复、把工作标为完成或执行问题中描述的操作。用户编辑过的文本会保留；旧问题会明确提示重新读取。

事项头部使用独立且有高度上限的滚动区域，最多占可用高度的 42%。头部和对话置于明确的纵向容器，分栏约束到实际窗口大小，输入框保持可见。原生测试按生产宿主配置验证支持的最小宽度 900 点及宽窗口；只测独立卡片无法验证整个布局。

`gtmux hq workspace list --overview --stored --json` 复用现有存储投影，不发现实时或历史会话，明确返回 `sources_included:false`。普通 list/participant 读取维持完整语义。Mac 先读事项摘要，再独立刷新所选对话；仅存储版本不变不能证明 agent 对话不变，因此存储摘要轮询仍读取当前对话。

实时/历史来源元数据使用独立队列，每分钟最多一次，另提供主动重试。完成后只把会话、历史参考、HQ 身份字段合并进当前快照，不把旧问题、旧版本或旧草稿覆盖回来。失败仅影响来源状态；未知不能显示成会话已消失，也不能错误提示启动 HQ。复用原有来源读取和多行输入框。

旧 CLI 仅在明确不支持 stored 参数的既有用法返回时，回退完整读取一次。超时、拒绝或成功响应损坏不会按此路径重试。请求超时文案不暗示提交已成功或已失败。

本机只读诊断单次观察到：完整总览约 8.09 秒、名单发现超过 10 秒测试上限、所选事项约 0.20 秒；开发二进制的存储读取约 0.94 秒。这些不是独占机器测量，也不是端到端 UI 耗时保证。没有答复生产问题或执行清理命令。测试使用合成数据和独立窗口，区分 AX 激活/几何与实际鼠标、VoiceOver、已安装 App 验收。
