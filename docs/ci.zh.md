# PR 检查

所有提交到 `main` 的 PR 都会启动 CI，包括外部贡献。**Checks selected** 摘要会列出
本次检查及对应的改动原因。检查不使用发版或签名凭据。新 GitHub 账号的首次贡献仍可能
受 GitHub 的审批规则限制；普通 PR 测试不进入测试包交付的受保护环境。

## 按改动选择检查

| 改动 | 检查 |
| --- | --- |
| 仅已识别的文档、翻译、规格 Markdown 或更新说明文本 | 规范与文档检查 |
| 菜单栏 Swift 源码或测试 | 规范与文档 + Swift 构建与测试 |
| 内嵌 Web 资源或浏览器测试 | 规范与文档 + 完整 Go + Web 逻辑与浏览器测试 |
| 手机/iPad JS/TS 源码或测试 | 规范与文档 + RN 类型、lint、Jest + Web + iOS 无签名构建 |
| iOS Swift/Objective-C 源码 | 规范与文档 + RN + iOS 无签名构建 |
| 推送中继 TS 源码或测试 | 规范与文档 + 中继 + 完整 Go + RN |
| 仅 Go 测试文件 | 规范与文档 + 完整 Go |
| 核心/API、依赖、构建配置、CI/脚本、隧道 Worker、未知路径 | 全部检查 |

明确的路径规则位于 `scripts/ci.py`。混合改动取并集；出现未知路径则全部检查。
重命名同时检查新旧路径，删除仍按原路径判断。版本信息缺失、差异读取失败或过大、
符号链接变化时也全部检查。不使用工作流级别的路径过滤。
在 GitHub 的 **ci → Run workflow** 手动启动时，全部检查都会运行。

每次都会检查所有工作流、范围判断/结果汇总/扫描失败的回归用例、严格规格、中英文配对、
源码设计规则、由真实代码生成的文档示例，以及使用模拟凭据的交付脚本。
`check-design.sh --source-only` 不编译 CLI、不解析传递依赖；对应约束由完整 Go 和平台
门禁验证。这些检查只能验证有机器依据的内容，不能替代文档语义审查。

## 怎样看结果

`ci-required` 是固定汇总检查。范围判断、规范检查和所有被选中的任务都必须成功；
缺失、失败、取消或跳过必跑任务都会使汇总失败。明确不受影响的任务可以跳过。
覆盖率保留七天；浏览器和原生构建失败时保留排查材料。PR 更新后，旧检查会取消。

维护者可以将 `ci-required` 配置为 GitHub 分支的必过检查。增加这个任务本身**不会**
开启分支保护；仓库权限规则仍单独管理。本次没有新增强制人工评审或部署审批。

## 本地验证及覆盖边界

提交前运行 `make check`，它仍执行完整核心检查，并补跑受影响的平台测试。
Web 可运行 `node --test internal/server/web/app.test.cjs`，再进入 `tests/web` 执行
`npm ci && npx playwright install chromium && npm test`。已有兼容 Chromium 时可设置
`GTMUX_TEST_CHROMIUM`，无需重复下载。

浏览器使用仓库真实 HTML/JS/CSS/xterm 和模拟 HTTP 数据，不会向真实窗格发送信息，
也不替代真实服务的契约测试。无签名原生构建包含 App、实时活动及通知扩展，但不验证
APNs、签名、安装或运行时无障碍。Safari、手机/iPad 真机布局、VoiceOver、终端跳转、
tmux-resurrect 仍需另记验收。移动端真实服务契约测试仍需显式配置
`GTMUX_E2E_URL/TOKEN`，跳过不能算通过。Linux Go 测试也不证明 macOS 专属运行行为。
