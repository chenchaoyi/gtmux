# 本地构建存储工作流

[English](development-storage.md)

适用于 iOS/macOS 开发、模拟器验证和发版准备：复用兼容缓存，完成每个任务的存储收尾。
这是操作流程，不会安装自动清理服务，也不扩大删除权限。沿用已有任务授权；已经明确授权
的清理范围不重复询问。

## 1. 开工前登记并采样

每个任务保留一份小型私有清单：负责人/session、仓库和源码提交、Xcode/SDK/架构、依赖锁文件
哈希，以及各产物路径、用途、重建方法、预计体积、保留理由和当前使用者。可重建产物、验收
证据、正式签名及恢复资料分开存放。

- 可重建产物放在本机缓存根下的任务/构建通道，例如
  `~/Library/Caches/gtmux-dev/<repository>/<task>/build/`。截图、失败/通过日志和回执放在独立证据目录。
- 签名 IPA、配套 `.xcarchive`/dSYM、上传回执及签名恢复资料放在私有持久目录，不混进
  待清理的 DerivedData。Pods、依赖和构建目录不放进 HQ 知识库或 notes。
- 保存带时间的 `df -k /System/Volumes/Data /System/Volumes/VM` 和精确可用字节，保留旧采样。
  APFS 共用空间池；仅靠 `statvfs` 的共享池读数，无法区分 Data 和 VM 各自增长。
- 用 `du -skx` 测互不重叠的候选目录。目录计数、稀疏文件、克隆和挂载的模拟器镜像不能
  直接当成可释放量，也不能重复相加。

以下是项目的保守复核阈值，不是厂商限制，更不是删除授权；应结合任务和近期实测调整：

| 检查项 | 默认处理 |
| --- | --- |
| 全新本地 iOS 依赖安装、归档和导出 | 按 25 GiB 可用空间规划；不足时优先使用既有云端分发流程。若依据实测采用更小预算，仍至少保留 2 GiB 安全余量。 |
| 带全新依赖的模拟器验证 | 任务预算 8 GiB；超过预算或更换工具链前重新采样。 |
| 剩余不足 10 GiB，或 VM 仍在增长 | 重新评估下一次写入，复用已验产物或改用云端构建。低于 2 GiB 时停止大写入，报告准确阻塞。 |
| 共享 Go 构建缓存超过 12 GiB，或已结束任务超过 1 GiB | 复核归属和复用价值，提交有边界的清理计划。这些是提醒阈值，不会自动删除。 |

## 2. 按兼容条件复用，隔离并行写入

| 内容 | 复用与归属 |
| --- | --- |
| npm、CocoaPods、gem 下载缓存 | 优先沿用包管理器现有缓存。除非需要隔离，不为每个 worktree 新建整套下载缓存；必须隔离时登记覆盖路径和退出计划。 |
| `node_modules`、`Pods`、已安装 gem | 在兼容、持续维护的工作树内复用，按该树锁文件安装。不同依赖或并行修改的工作树不能共用一套可变依赖目录。 |
| Xcode、SwiftPM、WDA 产物和索引 | 同一轮迭代保留可用缓存。兼容条件包括仓库/工作区路径、Xcode 构建号、SDK/平台、架构、锁文件和构建设置，由构建工具判断是否命中；App 版本相同并不足够。 |
| Go 构建/测试缓存 | 沿用工具的共享缓存和正常回收机制，不把 `go clean -cache` 或手工删哈希文件作为日常控容量手段。单独授权的全局重置会丢失有效缓存，必须预留重建成本。 |
| 已验证的 IPA 或模拟器构建 | 源码和配置一致时使用同一份字节。分发重试、切换兼容测试设备不应触发重建。 |

文档后续工作优先复用自己干净、兼容的工作树，不重复建树，也不接管别人正在使用的树。
工具链或锁文件改变后，重新登记兼容边界，不能默默留下另一套构建目录。

## 3. 删除前核准精确范围

1. 用当前回执/CI 核任务归属与完成情况，保留失败及通过证据。年龄、目录前缀或一次构建成功
   不能单独证明可删。
2. 对精确目录做有界 `lsof -nP +D <candidate>` 检查，同时核构建/设备活动，以及工具当前
   project/DerivedData 设置。超时或权限不足算未知；没有句柄也不等于已获授权。
3. 回收工作树前确认干净状态、检查忽略文件里的本地设置/密钥，并核实际合入结果。
   squash 候选未必是 main 的祖先，应使用 PR 的合入提交和源码树证据。
4. 保留小型本地配置，对要留下的证据、签名包和恢复文件做哈希。执行已授权操作前再核
   解析路径、inode/device、所有者、符号链接及嵌套挂载。
5. 用正常 `git worktree remove` 回收自己的已结束工作树，保留共享 Git clone/objects。
   Git 拒绝时先查原因，不追加 `--force` 或用整树 `git clean -fdx` 绕过。

日常任务清理不包括 swap、快照、SDK、模拟器运行时、全局缓存、个人文件、其他任务资料或
签名恢复数据。不能为让候选看起来空闲而终止/重启其他进程。更大范围需单独确认实际范围与授权。

## 4. 存储收尾也是完成条件

- 退出自己启动的临时测试驱动，恢复本任务设置、释放使用标记。保留所选设备和原 App 数据，
  不通过抹掉模拟器来收尾。
- 保留证据并确认已有授权后，回收已结束任务的本地中间产物、依赖和工作树副本。为明确后续
  保留的缓存必须有负责人、兼容条件、体积预算和下次复核点。
- 默认不留下无人负责的已结束构建目录。共享缓存和正式恢复资料按持久存储管理，不能遗留在
  一次性任务文件夹里。旧版本需在验收及恢复/保留要求核准后复核，不能仅按版本数量或年龄删除。
- 独立验证路径消失、保留文件哈希和共享 Git 根完整。记录结束时 Data/VM 读数、失败/跳过项
  以及每个保留路径的理由。分开报告“删除的目录计数”和“实际观察到的共享池可用变化”。
- 交清理回执，并在知识库只留小型经验/索引。仍在用或无法判断的候选要交具体例外与下一步，
  不悄悄遗留数 GB 产物，也不留下无人执行的后台承诺。

签名包的边界见 [iOS 分发](../mobileapp/DISTRIBUTION.zh.md)。私有清单和清理回执不进 Git；
公开 CI 产物和知识条目不得带凭据、设备身份或私有安装地址。
