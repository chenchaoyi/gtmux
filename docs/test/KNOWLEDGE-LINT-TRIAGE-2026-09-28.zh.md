# 知识检查提示分诊（2026-09-28）

本机私有 HQ 报告逐项列出原有 27 组相似条目的两个 ID、台账来源字段和不合并的判据，并列出无链接条目的来源字段。条目正文及涉及本机账号的细节没有提交到公开仓库。

| 提示 | 分诊依据 | 处理后 |
| --- | --- | --- |
| 27 组 `near-duplicate` | 逐组读正文、适用范围和 provenance。0 组可确认为同义重复；22 组原已直接互链。其余包括不同的故障判断、独立脚本与总流程、同一事故的不同教训。 | 给 2 组确有主从关系的条目补真实链接；另外 3 组不强行互链。文本变化后仍有 25 组相似候选，标为 `review`，不当作 25 个缺陷。 |
| 265 条 `orphan` | “没有 `[[链接]]`”只说明图上独立。条目仍可按主题、全文搜索和邻近检索找到；链接不是台账必填项。 | 发现 2 条只有标题，按事件记录或只读复现实验补正文和验证边界；1 条脚本说明补“脚本存在、未绑定单次故障”的来源状态；3 处正文已经指向现存条目的地方补真实链接。余 262 条均有正文、provenance 和台账序号，作为 `info` 独立条目保留。序号本身不证明历史事实。 |
| 双语链接盲区 | 原检查器只扫主语言正文，另一语言中的知识引用没有参与断链和入链判断。 | 两种语言均检查并计入图边。一处英文示例 `[[links]]` 排除为占位符，一处指向已被替换条目的历史引用改写为历史说明。断链、歧义及过时链接均为 0。 |

检查器保留 JSON 的 `orphan`、`near-duplicate` 名称以兼容旧使用方，新增 `severity`：`info`、`review`、`issue`。终端输出和 HQ self-check 摘要明确区分这些级别。没有为清零计数而删除条目、合并不同事实或造链接。
