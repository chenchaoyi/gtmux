## 日志与知识现状

- 诊断日志：`internal/diag` 的本地 JSONL 有稳定事件名、参与者、目标、结果和标量属性；按天轮转，保留上限为 30 天或 100 MB，单条 4 KB。`gtmux logs` 支持过滤、统计、JSON 和持续读取。手机/iPad 在设备上另存有界诊断缓冲（500 条、200 KB）。
- 会话事件：`internal/events` 的追加式日志有序号、缺口检测和轮转；`gtmux events --all --json` 能追踪会话与 HQ 审计。此次增加的维护完成事件用 `kind`、`request_at` 明确对上请求。
- HQ 知识：`internal/knowledge` 用追加式台账记录条目和操作，带事件序号、范围、来源、主题、类型、受众等结构化字段；候选队列和无模型采矿器收集待处理线索。检查时有 724 个在库条目、2 个候选。`knowledge lint` 报出断链 66、近似重复 26、孤儿 265、未标敏感 1 等待审核问题。这些条目涉及事实与隐私判断，本轮没有自动改写。
- 可分析性边界：诊断日志、会话事件、知识台账是三份结构化存储；维护记录现在可直接关联。其它跨存储活动还没有统一操作 ID，常需按时间、pane 或 agent 会话关联。日志写入按设计为 best effort，磁盘写入失败不阻断主操作，因此不能声称记录了**每一次**活动。私有知识的候选处理结果可查，但质量依赖 HQ 实际做完并写回执；未做完会在 doctor 显示待完成。

## 验证限制与后续观察

- 本机磁盘检查时约 11 GB 可用；没有运行模拟器、原生手机构建或安装，也没有发布版本。
- Node 22 按 CI 原命令运行 Jest 返回成功，全部断言通过；部分旧组件测试仍有 React 定时器/渲染任务在 Jest 环境退出后才结束，CI 会输出 worker 退出警告。这不改变本轮断言结果，值得单独清理测试资源。
- Web VM 测试验证脚本交互，真实浏览器布局与辅助技术朗读仍需设备人工验收。
- 知识库 lint 队列、跨日志统一操作 ID、日志持久化失败的可见性需要后续设计；涉及私有知识内容的取舍留给 HQ/人工逐条审核。
