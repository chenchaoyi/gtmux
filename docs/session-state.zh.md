# 会话状态与时长

CLI、Mac 菜单栏、移动 App 和浏览器共用 Go 核心提供的会话状态。
终端重绘本身不代表新任务开始。

如果旧 Codex 活动标记一直残留，但已经有更新的结束观测，且前端绑定不可用，
gtmux 仍可识别没有执行、待提交消息、权限确认或进程工作迹象的就绪终端。
此时显示空闲，保留所有生命周期记录，不发送完成通知，也不标记为刚完成。
刚开始的任务和已验证的前端仍沿用更严格的身份与轮次检查。

如果终端确实正在执行，早于结束观测的旧时间不能用于计算本次时长。
能够识别当前 Working 行的计时时，使用该计时；无法确定时隐藏时长，仍显示进行中。
旧版服务端维持原有计时方式。

同一秒内重复读取状态时，会保留刚观测到的 CPU 工作信号，但不延长其有效期。
时间倒退或 CPU 计数重置不会作为新的工作证据。

恢复记录以完整文件原子替换。Codex hook 保存与前端心跳共用绑定锁，
发生并发竞争时不会覆盖其他绑定；归属未知或锁忙仍保守处理。
这不会自动修复损坏的历史记录，也不会恢复任何会话。
