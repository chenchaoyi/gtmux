# 事项对话管理：诊断与审阅

用户看到的变化：打开「对话与记录」，先辨认本事项有哪些工作对话与背景记录，再选择查看、添加或调整。日期、移入事项、拆分选择不再同时挤在默认页面。

## 当前事实与概念

已查看用户提供的 [改前截图](01-before.png)，定位到 **macOS 原生 HQ 工作台 → 事项详情 → HQWorkspaceParticipants sheet**。不是手机或 Web 页面。分支从干净状态快进到 `d5029932` 后实施；没有操作其他 checkout、应用实例、设备或服务。用户提供的 AGENTS 指令已读；本仓库及父目录没有可读取的 AGENTS.md，另已遵循 CLAUDE.md、设计规范和 product-design:audit。

| 对象或旧词 | 核实的数据语义 | 展示决策 |
|---|---|---|
| 会话 | 一次 agent 对话，由 agent、home、session ID 唯一标识 | 保留为可辨认的工作对话；名称说明内容，agent 说明执行者 |
| pane / loc | 可变的终端位置，不是对话身份 | 次要来源信息；当前状态只来自身份完全匹配的终端 |
| 事项 | 独立的长期目标，有自己的 HQ 讨论和明确状态 | 页头始终显示本事项名称；不会用 agent 空闲推断事项完成 |
| active participant | 未移除的收录关系，可能只是历史参考 | 不称「运行中」；与进程状态分开 |
| 关联时段 | 事项原文阅读使用的 from/until 范围 | 以「持续收录」或「历史参考／已停止收录」摘要呈现；调整时才显示起止时间 |
| 目标事项 | 既用于单条 move，也用于整个事项 merge | 分开进入两个流程；不共享上一步的默认选择 |
| 历史参考 | 固定范围的背景记录，必须有结束时间 | 保留角色差异；不会把历史参考和持续收录合为同一概念 |

`conversations` 是当前终端中的精确身份；`references` 是有本地原文的过去记录。**未找到终端不证明进程已结束**，收录范围结束也不证明 agent 停止。当前来源的 `since` 是状态开始时间，历史来源的 `since` 是记录更新时间；都不能称为最后发言时间。没有可靠活动时间时明确显示不可用。

## 改前诊断（截图 01）

1. 标题没有说明是哪个事项的哪些对象。工作名称、pane、agent 与拆分勾选混在一行，容易误认成终端管理器。
2. 单条日期、单条转移、添加表单和整个事项合并／拆分同时出现，阅读、添加、纠正归属这三个常见任务没有主次。
3. 「目标事项」在两个不同作用范围里复用，底层还共用 destination 状态。用户为单条转移选过的值会进入整个事项合并。
4. 「移出」直接执行，没有当场说明只解除此事项的收录关系。旧合并有确认，原始记录保留是已有正确边界，应继续保留。
5. 无法从截图断言完整无障碍支持。窄宽时水平表单、长名称和无可见用途的勾选有阅读与定位风险；需实际控件验证。

## 真实形态的使用流程

以下改后图片是**本分支真实 SwiftUI 视图、合成数据、原生测试窗口的内容截图**，不是绘制的设计稿；不包含已安装应用或用户当前会话的操作。改前为用户提供的裁剪截图，改后主窗口为 660 × 640 pt，并非同一设备像素裁剪，不作像素还原声明。

| 步骤 | 用户动作与结果 | 状态 / 证据 |
|---|---|---|
| 1 | 打开「清理磁盘，保留正在使用的工作区」的对话。辨认当前空闲的 Codex 和过去的背景记录，分别看到来源、状态时间／记录更新时间及收录范围。 | 已检查：[改后清单](02-after-list-zh.png)、[英文](layout-list-en-660-light.png) |
| 2 | 点「查看原始对话」，读取“先汇报再清理”的原始问答，不发送消息。 | 已操作，并检查窄宽完成按钮／尺寸；原文页子弹窗截图受环境限制，视觉未验 |
| 3 | 点「添加对话」，选“核对构建缓存的保留规则”，确认从现在收录；需要过去内容时再改开始时间。 | 已操作：[选来源](03-choose-conversation-zh.png)、[确认范围](04-add-range-zh.png) |
| 4 | 点某条「调整」，按需调整范围、移动或移除。移动确认指明来源、目的地和单条范围；取消移除不提交。 | 已操作：[就地操作](06-adjust-actions-zh.png)、[范围](05-adjust-range-zh.png)、[移动](08-move-zh.png) |
| 5 | 需要改变事项组织时，单独进入「拆分或合并此事项」。拆分只移选中对话、原 HQ 讨论留下；合并全部汇入并结束来源事项。 | 已操作：[窄宽整理](layout-organize-en-350-dark.png)；原生合并确认的图片捕获受限，确认与取消已做实际控件测试 |

普通阅读只需第一、二步；已有对话要归入此事时只需第三步。关联角色与时间边界仍在数据和操作中保留；只将它们从默认表单中收起，没有新增删除原始对话或停止 agent 的动作。新任务、事项内回复和 HQ 运行记录的入口、发送范围不变。

## 可复用原则（区别于上述本次事实）

先让用户辨认对象与用途，再提供调整；相似术语涉及不同作用范围时，应通过入口、对象名称与确认同时区分。进程是否存在、内容是否继续收录、事项是否完成是三条独立状态轴。时间必须标明其来源语义，不把“观察状态的时间”包装成“工作最近有进展”。
