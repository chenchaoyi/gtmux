# Honest recovery guidance, project-material inventory and loading parity

HQ can accumulate historical project payloads and legacy full relay observation
exports. Doctor currently promises retries without knowing whether the original
producer remains available, and browser/Mac branded loaders drifted from App's
accepted moving-focus design. Keep recovery limits and input authority unchanged.

Add conservative read-only material classification, document the difference between
HQ directory size, recovery capacity and snapshot retention, and structurally
recognize legacy observation exports only inside automatic core selection. Actual
operator cleanup is separately authorized, privately verified and project-owned.
Align the existing shared Web and Mac branded loading components with App's fixed
three-pane1.8s focus. Preserve system progress controls and agent state semantics.

## Surfaces

- terminal (incl. attach): CLI doctor reports material categories and conditional
  recovery guidance; attach is a PTY and has no branded page-loader counterpart.
- menubar: consumes the same doctor projection; its shared branded progress mark
  adopts the focus cycle and static reduced-motion/inactive state.
- phone: existing shared LoadingMark is the accepted reference; no new mobile
  source, OS splash, system progress or input-authority change.
- iPad: same unchanged mobile component as Phone, including regular layouts.
- Web: every branded loader entry shares the corrected factory/CSS motion and
  decorative accessibility contract, with real hosted narrow/wide rendered tests.

## Verification boundary

Reviewed design precedes test source. Synthetic Go tests cover scope/unknown/include
protection and stopped/unknown/live evidence; hosted Playwright and SwiftUI pixel
renders cover motion frames and static preferences. Independent review remains a
separate gate. No real session fault injection, automatic project deletion, phone
installation, Safari/VoiceOver claim or restore into production is part of this PR.
