# Make matter conversation management understandable

## Why
The native management sheet exposes association metadata and whole-matter operations at once. Users cannot identify the underlying conversations or predict the scope of a change. One shared destination also leaks between per-conversation moves and whole-matter merges.

## What changes
- Lead with the current matter and identifiable conversation records: task title, agent, verified current terminal state, state time, and collection purpose/range.
- Browse available and saved conversations before configuring an addition. Saved records are bounded historical references; missing live identity never proves a process ended.
- Show time-range and destination controls only inside their respective task. Confirm removals, individual moves, splits and whole-matter merges with named scope and consequences.
- Retain immutable identities, revision checks, original records, HQ message routing and the existing metadata protocol.
- Use native controls, shared typography, bilingual copy and narrow reflow. Test synthetic native control actions separately from visual review.

## Surfaces
- Terminal: protocol and command behavior unchanged; existing metadata operations retained.
- Menu bar: native HQ matter header, management list and focused editors redesigned.
- Phone: no equivalent matter-management route; no mobile app changes or device acceptance claimed.
- iPad: same boundary as Phone; no app changes.
- Web: no equivalent matter-management route; no HTTP writes added.
