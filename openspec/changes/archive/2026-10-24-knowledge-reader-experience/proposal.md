# Knowledge reader experience

## Why
The knowledge manager exposes ledger vocabulary without explaining what readers can do. Audience is hidden until a dialog, pending work resembles completed application, and Chinese screens show raw kind/provenance/topic keys. Mac and mobile use different action labels.

## What changes
- Show the recorded use and its processing state on every entry, including the default HQ lookup behavior.
- Explain HQ lookup vs standing HQ rules, local agents, repository instructions and product feedback.
- Localize vocabulary, lead with prose titles and move identifiers/implementation details into a compact disclosure.
- Use consistent action names and explain the next step before confirming; keep the current entry after a successful non-removal action.
- Align mobile reading and management copy, backup naming, docs and regression coverage.

## Boundaries
No ledger migration, automatic promotion/carry, new authorization, product publication or changes to real knowledge files. The displayed scope is recorded intent and workflow progress, not evidence that a running agent loaded a file. Existing machine render/index behavior is retained.

## Surfaces

- terminal (incl. attach): existing ledger commands, output fields and permissions unchanged; reader docs clarify their relationship to UI actions.
- menubar: native knowledge list, detail, usage dialog, action continuity and backup context updated.
- phone: shared knowledge presentation, record disclosure, action labels, busy state and continuity updated.
- iPad: same KnowledgeSheet and presentation model in its regular two-column shell; no second implementation.
- web: not applicable; paired/share Web has no knowledge-manager surface, and none is added.
