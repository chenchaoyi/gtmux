## Why
Completed PID-less Codex observations occupy the live overview for the entire twelve-hour fallback grace even though saved history does not establish a live process. External groups also lack the collapse control available on status groups. Codex hook workers lose their original ancestry when detached, preventing ordinary process-exit pruning.

## What Changes
- Add independently persisted collapse controls to both non-tmux groups in the Mac popover.
- Omit completed, PID-less, unfollowed Codex observations from the live radar without deleting history, observations or consent.
- Capture a bounded, revalidated agent-process snapshot before detaching Codex hooks. Carry it privately to the worker; compare exact process birth where available when pruning records.

## Surfaces
- CLI: consumes the radar filtering and process-exit evidence; transcript-by-ID remains available.
- macOS: external and elsewhere headers fold with counts retained.
- iPhone: consumes the same radar filtering; no UI change.
- iPad: consumes the same radar filtering; no UI change.
- Web: consumes the same radar filtering; no UI change.

## Boundaries
Turn completion is not frontend shutdown. An absent PID is not proof of exit. Shared backend process liveness does not prove exclusive control. This change grants no input, does not infer historical launcher names, and does not delete saved conversations or alter follow permissions. DSH's saved-session discovery is unchanged.
