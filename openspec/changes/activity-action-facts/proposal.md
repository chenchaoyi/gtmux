# Preserve recorded Activity action facts

## Why
A skill read appears as a bare SKILL.md filename, and web search/open/find all appear as page browsing. The recorded calls contain more precise intent that can be shown without inventing extra executions.

## What Changes
Keep the existing operation vocabulary and add optional bounded action/subject_count facts from explicit tool methods, complete recognized argument structures or native parsed read targets. Share bilingual labels/icons and target summaries across App, browser and Trace. A multi-file exec remains one call, and raw inputs and detail references remain authoritative.

## Surfaces
- terminal: unchanged native TUI; no new input or interception.
- menubar: existing navigation remains; shared radar contract is additive.
- phone: precise compact Activity and Trace labels.
- iPad: the same shared presentation and original touch targets.
- Web: generated canonical presenter matches App and Trace.

## Impact
Transcript adapters and bounded cache accounting, additive API metadata, shared consumer presentation and deterministic fixtures only. No result-body interpretation, filesystem skill discovery, fabricated child calls, service restart or live transcript mutation.
